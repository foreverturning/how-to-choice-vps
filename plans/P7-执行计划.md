## 2. WorkBuddy 子 agent：创建 + 调用方式

**落盘**：在仓库内 `.workbuddy/agents/` 新建 8 份定义文件，ID 沿用 `vps-{spec-writer,price-researcher,cost-modeler,chapter-writer,lab-writer,toolkit-writer,appendix-writer,qa-reviewer}.md`，作为可复用契约资产。

**frontmatter 用 CodeBuddy/plugin 格式**（`name` / `description` / `tools` / `model: inherit` / `color`），例如：

```yaml
---
name: vps-chapter-writer
description: 按 QA 报告定点修复 chapters/** 正文（仅本项目，不改数据层/ops/不执行 git）
tools: Read, Glob, Grep, Edit
model: inherit
color: blue
---
```

> 依据见文末「依据与脚注」：WorkBuddy 专家包规范禁写 `tools` 只约束专家包；此处是 subagent 定义，插件市场样例普遍带 `tools`。文件头加注释说明此归属，并注明「若将来注册为专家包，删 `tools`、补 `displayName`/`profession`/`maxTurns`」。`tools` 白名单排除 `Bash`（禁 shell/git），修复类不含 `Write`（不得新建文件），QA 类含 `Write`（新建 Q2/Q3）。`mode`/`steps`/`permissions` 不写入（opencode 专属）。

**正文 100% 原文复用** `.opencode/agents/*.md` 的「开始前必读 6 项 / 写作要求 / 硬性约束 / 回执格式 / QA 8 项检查」，仅按角色替换可写目录，并追加「本次注入：口径裁决卡 + 目标文件路径 + 精确改动条目 + `SendMessage(recipient:"main")` 回传」。

**调用（关键降级）**：执行环境的 `Agent` 工具 `subagent_type` 是固定枚举，自定义 ID 未必可加载 → **优先用 `general-purpose` 派发，把对应定义文件的正文整段注入 prompt**；若环境接受自定义 `subagent_type`，则 `name` 与 `subagent_type` 都传 agent ID。同一条消息并行 spawn。子 agent 看不到主对话历史，每个 prompt 必须显式注入：①6 项必读；②口径裁决卡；③目标文件路径 + QA 编号与行号；④回执要求（改动清单／未改项／自检 8 项／字符数／链接）。

**执行角色约定**：`chapter-writer` ×4（01/02/03/04）、`lab-writer` ×1（Lab3）、`qa-reviewer` ×2（Q2/Q3 + 全库只读复核）；其余 3 份只落盘。`_shared/三档成本模型.md`、`ops/*`、`00-总纲.md`、全部 git 操作由主会话独占。
