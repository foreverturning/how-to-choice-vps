# Lab 6 低价 VPS 体检

> 做完你会得到：一份填满数字的体检报告、一张 100 分制评分表，以及一句明确结论——**可用 / 仅玩具 / 退货**。
> 对应总纲：Lab 6 ｜ 对应文章：[05 成本解剖篇](../chapters/05-成本解剖篇.md) 的 5.8 节、[07 低价机篇](../chapters/07-低价机篇.md) 的 7.6 节 ｜ 预计耗时：2–3 小时 + 连续 3 个晚高峰

---

## 目标

对**你已经买到手**的一台低价 VPS 做一次完整体检，用可复现的命令把“感觉不太行”变成“哪一项不行、差多少、值多少钱”。

体检要回答四个问题：

1. 它到底是什么？独立 IP 还是 NAT、KVM 还是 OpenVZ、新盘还是高龄二手盘。
2. 它承诺的东西兑现了几成？标称 200M 的机器，晚高峰实际跑多少。
3. 它的年价落在哪一档成本地板上？低于地板的那部分，被转移到了哪里。
4. 结论是什么？能放业务、只能当玩具，还是该退货或弃用。

顺序很重要：**先查不要钱的（订单、IP、硬件、合规），再查要花钱的（带宽、快照）**。很多机器在第 2 步就该结束体检，不必再花流量费。

范围也说清：本 Lab 不测 DDoS 清洗、不测长期故障率、不测真实业务并发。这些靠时间和口碑，不靠三小时采样。

## 前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| 服务器 | 1 台已购买的低价 VPS，能 SSH 登录 | 只测自己的机器；没有就先用月付买一台，别年付 |
| 权限 | root 或 sudo | `smartctl`、`fio`、`mpstat` 需要 |
| 本地环境 | Linux/macOS shell，或 Windows + WSL | 需要 `ssh`、`curl`、`ping`、`mtr`、`nc` |
| 对端机器 | 一台你控制的、线路较好的机器（可选但强烈建议） | `iperf3` 必须两端配合；没有就只用 `curl` 单线程测 |
| 账号纪律 | 独立邮箱、独立密码、独立支付方式 | 不用主账号、不绑主邮箱、不开自动续费 |
| 预算 | 机器本身的价格 + 约 5–20GB 测试流量 + 快照费用 | 具体量级见步骤 1、8、12，均标注“会产生费用” |
| 时间 | 2–3 小时一次性检查 + 3 晚 20:00–22:30 采样 | 晚高峰指北京时间 20:00–22:30 |

```bash
mkdir -p ~/lab6 && cd ~/lab6
```

## 步骤

### 步骤 1｜记录订单与续费价（会产生费用）

- **做什么**：下单本身会产生费用。把订单页、配置页、计费周期、续费价、退款条款各截一张图，存成 `lab6-order-*.png`。同时在 `lab6-order.md` 里抄下六行：付款金额、计费周期、**续费价**、带宽标称、月流量、IP 类型。
- **看什么**：首年价和续费价是不是两个数。首年 30 元、续费 300 元的机器，真实年成本是 300 元，不是 30 元。
- **成功标志**：能写出“这台机器第 2 年要付多少钱”。写不出来，说明条款里没写，直接记一条风险。
- **费用**：机器价格本身。2C2G 档常见量级：A 档约 600 元/年（快照 P-001，2026-11，续费价待核对）、B 档 138–408 元/年（快照 P-011、P-013，2026-11）、C 档 72–104 元/年（快照 P-017、P-018，2026-11）。

### 步骤 2｜查 IP 形态（不花钱，5 分钟）

- **做什么**：同时看三个地方——出口 IP、网卡地址、IP 归属。
- **命令**：`curl -4 -s ifconfig.me`、`ip -4 addr show`、`whois <IP>`、从外部机器 `nc -vz <IP> 22`。
- **判读**：
  - 网卡是 `10.x` / `172.16.x` / `100.64.x`，出口却是公网地址 → **NAT**。
  - 出口 IP 每次重连都变 → **动态 IP** 冒充固定 IP。
  - `whois` 的 `country` 与宣传地区不符，或 `netname` 是住宅宽带 → 转卖或套牌。
  - 外部 `nc -vz` 连不上 22 但机器上 `ss -tlnp` 显示在听 → 端口没映射，或上游有防火墙。
- **成功标志**：写清一句话——“独立 IPv4 / 共享 IPv4 / NAT / 仅 IPv6”。
- **为什么排第二**：IP 形态决定后面一半结论。NAT 机谈“固定 IPv4”没有意义，价格对照也要重算。

### 步骤 3｜查硬件与虚拟化

- **做什么**：确认虚拟化类型、CPU 型号、内存实际可用量、磁盘是不是 SSD、根分区剩多少。
- **命令**：`systemd-detect-virt`、`lscpu`、`free -h`、`lsblk -d -o NAME,ROTA,MODEL,SIZE`、`df -h`。
- **判读**：
  - `systemd-detect-virt` 返回 `kvm` 是完整虚拟化；返回 `openvz` / `lxc` 是共享内核，后面很多测试会失真。
  - `lscpu` 里的型号要能和宣传对上。写着“2 核”但 `Model name` 是十年前的 E5，属于二手平台。
  - `free -h` 的 `total` 明显小于标称（比如买 2G 只有 1.8G）是正常的系统占用；但如果 `Swap` 已被大量使用，说明内存不够用。
  - `lsblk` 的 `ROTA` 为 1 是机械盘；为 0 是 SSD/NVMe。`MODEL` 为空或写着 `vda`，说明是虚拟盘，看不到物理型号。
  - `df -h` 看根分区真实可用空间，后面跑 `fio` 要用它算安全写入量。
- **成功标志**：`lab6-hardware.txt` 里有虚拟化类型、CPU 型号、内存总量、磁盘类型、可用空间五项。

### 步骤 4｜查磁盘健康与通电时长

- **做什么**：能读到 SMART 就读，读不到就记录“读不到”这件事本身。
- **命令**：`sudo smartctl -a /dev/sda`、`sudo smartctl -a /dev/vda`、`sudo nvme smart-log /dev/nvme0`。
- **判读**：
  - `Power_On_Hours` 超过 3 万小时（约 3.4 年连续运行）→ 二手盘。
  - `Reallocated_Sector_Ct` 非 0、`Pending_Sector` 非 0 → 盘在坏，别存数据。
  - NVMe 的 `percentage_used` 超过 20% → 寿命接近尾声。
  - 读不到 SMART：KVM 的 virtio 盘通常不透传，这是正常的；OpenVZ 读不到则是结构性的，见常见问题 2。
- **成功标志**：要么有通电小时数，要么有一条明确写清“平台不透传 SMART”的记录。两种都算完成。

### 步骤 5｜测 CPU（低峰跑）

- **做什么**：单线程、双线程各跑 30 秒，记录 `events per second`。
- **命令**：`sysbench cpu --threads=1 --time=30 run`、`sysbench cpu --threads=2 --time=30 run`。
- **判读**：重点不是跑分，是**两个比值**。
  - 双线程 ÷ 单线程 ≈ 2，说明两个核是真给到你了；明显小于 1.8，说明核在抢。
  - 同一型号、同一代际的机器之间横向比，差 30% 以上就要怀疑超售或降频。
- **成功标志**：两组 `events/s` 和 `total time` 都记进 `lab6-cpu.txt`，并注明跑的时间点（低峰还是高峰）。

### 步骤 6｜测磁盘（会写文件）

- **做什么**：先 `df -h` 确认剩余空间，再在**独立目录**里跑 4K 随机读写和顺序读，各 30 秒。
- **命令**：见下方“命令”区第 4 组。测试文件固定放 `/root/lab6/`，大小 512MB。
- **判读**：
  - 4K 随机写低于 500 IOPS → 机械盘或严重限速。
  - 顺序读远低于 100 MB/s → 大概率是网络存储。
  - 同一台机器两次结果差 3 倍以上 → 邻居在抢 IO。
- **成功标志**：拿到 `iops` 与 `bw` 两个数，并确认测试文件已删除、`df -h` 回到测试前的数值。
- **纪律**：绝不在生产盘、数据盘、挂载了业务目录的分区上跑。写坏数据这类事故，一次就够记一辈子。

### 步骤 7｜测内存

- **做什么**：跑一次内存带宽，并在跑之前和跑之后各看一次 `free -h`。
- **命令**：`sysbench memory --memory-block-size=1M --memory-total-size=2G run`。
- **判读**：
  - 吞吐明显低于同代际水平，可能是内存被 balloon（气球驱动回收）或被限速。
  - 跑完之后 `free -h` 的 `available` 没有恢复，说明有内存泄漏或缓存异常。
  - 有 `Swap` 且被频繁使用，说明这台机器的 2G 是“名义 2G”。
- **成功标志**：`lab6-mem.txt` 里有一次吞吐值 + 前后两次 `free -h` 快照。

### 步骤 8｜测网络吞吐（会产生费用）

- **做什么**：用 `iperf3` 在你自己的两台机器之间对测，先测下行（`-R`），再测上行（不带 `-R`），各 30 秒、4 并发。
- **命令**：见下方“命令”区第 6 组。
- **判读**：
  - 输出单位是 Mbits/sec，除以 8 才是 MB/s。
  - 单线程跑不满、多线程能跑满 → 单流限速。
  - 白天能跑满、晚高峰掉一半 → 共享带宽。
  - 完全跑不动但 `curl` 小文件正常 → 被 QoS 限了大流量。
- **成功标志**：拿到上行、下行两组数，并注明“几点测的、对端在哪”。
- **费用**：**会产生费用**。30 秒 × 4 并发跑满 200M，单向约 0.75GB；两个方向加三轮复测，约 5GB 量级。按流量计费的机器要盯着控制台；标称“不限量”但写“公平使用”的机器，超额可能被限速。没有对端机器时，改用 `curl` 下载 100MB 文件，只测下行，量级约 0.1GB/次。

### 步骤 9｜测回程与丢包

- **做什么**：对三个目标各跑一次 `mtr`：一个国内目标、一个你用户所在地区的目标、一个国际目标。
- **命令**：`mtr -rwzc 30 "$TARGET"`，配一次 `traceroute -T -p 443 "$TARGET"`。
- **判读**：
  - 丢包集中在某一跳之后的所有跳 → 那一段出了问题；只在最后一跳丢，多半是目标侧限速。
  - 回程出现 `202.97` 而不是 `59.43` → 不是 CN2 GIA。宣传 CN2 的机器，这一步就能验真假。
  - 三网某一网绕路 200ms 以上 → 可能是单线加 BGP 广播，不是真多线。
- **成功标志**：三条 `mtr` 的文本输出存盘，标出丢包最大的一跳。

### 步骤 10｜晚高峰连续采样（会产生少量流量）

- **做什么**：在 20:00–22:30 之间，每 5 分钟采一次，连续 3 晚。采集项：`ping` 的延迟与丢包、一次小文件下载速率。
- **命令**：见下方“命令”区第 9 组，建议挂在 `tmux` 里跑，别占着 SSH。
- **判读**：
  - 规律性劣化（每天同一时段掉）→ 共享带宽被邻居占满，这是超售的直接证据。
  - 随机抖动、无规律 → 可能是本地网络或上游抖动。
  - 晚高峰只有凌晨的 50% 以下 → 按“标称的一半”重新估这台机器的能力。
- **成功标志**：得到一张 3 天 × 30 个点的表，含时间、延迟、丢包、下载速率四列。
- **费用**：**会产生少量流量**。每次下载 10MB、每天 30 次、三天约 0.9GB，属可接受量级。别再叠加 `iperf3`。

### 步骤 11｜查超售与 steal

- **做什么**：在晚高峰跑 `mpstat`，看 `%steal`；同时看 `top` 的负载与 `/proc/pressure/cpu`。
- **命令**：`mpstat -P ALL 1 5`、`top -bn1 | head -5`、`cat /proc/pressure/cpu`。
- **判读**：
  - `%steal` 长期大于 5%、晚高峰大于 20% → CPU 被超售，你的核在给别人打工。
  - `load average` 持续高于核数，但你的进程并不忙 → 同上。
  - PSI 的 `some avg10` 持续大于 10 → 任务在等 CPU，体感会明显卡。
  - `%steal` 为 0 且负载平稳，说明这一项过关，但不代表带宽没超售——两项要分开看。
- **成功标志**：`lab6-steal.txt` 里有 5 次采样值和时间戳。

### 步骤 12｜查快照与备份（会产生费用）

- **做什么**：登录控制台，确认三件事：有没有快照功能、快照怎么收费、备份是否自动。
- **看什么**：
  - 有快照但按容量收费：先看单价，再决定要不要做一次基线快照。
  - 只有“重装系统”没有快照：等于没有备份能力，数据风险自负。
  - 备份在“同机房同存储”：能防误删，防不了整机跑路。
- **成功标志**：截图控制台的快照页与计费说明，写一句“能否在 30 分钟内恢复一台可用机器”。
- **费用**：**会产生费用**。快照按占用容量计费，一台 40GB 盘做一次全量快照，常见量级是几元到十几元/月；做之前先确认单价，别把体检做成账单事故。

### 步骤 13｜查合规与许可证

- **做什么**：查经营主体、许可证、能否开票。这一步不花钱，但最能一票否决。
- **怎么做**：
  - 官网底部/关于页找公司全称，去工信部 `dxzhgl.miit.gov.cn` 查 IDC/ISP 许可信息。
  - 国内建站要查 ICP 备案：`beian.miit.gov.cn` 输入域名查主体。
  - 问客服要发票：能开什么票、几个点、要不要加钱。
  - 查 IP 信誉：`abuseipdb.com` 看 90 天内滥用记录，分数高于 25 视为脏 IP。
- **判读**：查不到主体 + 只收年付 + 无发票 + 拒绝任何退款，四条同时命中，直接判“弃用”，不用再往下打分。
- **成功标志**：`lab6-compliance.md` 里三行：主体名称、许可证查询结果、发票答复。

### 步骤 14｜打分与出结论

- **做什么**：把前 13 步的结果填进下面的评分表，算总分，对照三条结论线。
- **成功标志**：报告最后一页只有一句话结论，加三条支撑理由，每条都带数字。
- **纪律**：分数必须能被别人用你的原始输出复算。写“网络一般”不算结论，写“晚高峰下行 96Mbps，为标称 200M 的 48%，丢包 1.8%”才算。

## 命令

以下命令按步骤分组，整段可复制。尖括号是占位符，替换成你自己的地址，不要把真实 IP、密钥写进公开文档。

```bash
# 0) 先填三个变量，后面整段都能直接跑
IP="你的服务器IP"        # 改成你的机器 IP
PEER="对端IP"            # 改成你的 iperf3 服务端 IP
TARGET="1.1.1.1"         # 延迟与丢包采样目标

# 1) 基础信息与虚拟化
systemd-detect-virt
lscpu | grep -E "Model name|^CPU\(s\)|Thread|MHz"
free -h
df -h
lsblk -d -o NAME,ROTA,MODEL,SIZE

# 2) IP 形态：三条一起看，缺一条就会误判
curl -4 -s ifconfig.me; echo
ip -4 addr show
ip route get 1.1.1.1
whois "$IP" | grep -Ei "netname|country|org|descr"
nc -vz "$IP" 22

# 3) 磁盘健康（读不到不算失败，记录即可）
sudo apt install -y smartmontools
sudo smartctl -a /dev/sda | grep -E "Device Model|Serial|Power_On_Hours|Reallocated_Sector"
sudo smartctl -a /dev/vda 2>/dev/null | head -20
sudo nvme smart-log /dev/nvme0 2>/dev/null | grep -E "power_on_hours|percentage_used"

# 4) CPU 与内存
sudo apt install -y sysbench
sysbench cpu --threads=1 --time=30 run
sysbench cpu --threads=2 --time=30 run
sysbench memory --memory-block-size=1M --memory-total-size=2G run

# 5) 磁盘 IO：只写 /root/lab6，测完立刻删
mkdir -p /root/lab6 && cd /root/lab6
fio --name=randrw --directory=/root/lab6 --ioengine=libaio --rw=randrw \
    --bs=4k --size=512M --numjobs=1 --runtime=30 --time_based --group_reporting
fio --name=seqread --directory=/root/lab6 --ioengine=libaio --rw=read \
    --bs=1M --size=512M --numjobs=1 --runtime=30 --time_based --group_reporting
rm -f /root/lab6/randrw /root/lab6/seqread

# 6) 网络吞吐（会产生流量费用；需要你自己的对端机器跑 iperf3 -s）
iperf3 -c "$PEER" -t 30 -P 4 -R
iperf3 -c "$PEER" -t 30 -P 4

# 7) 回程与丢包
mtr -rwzc 30 "$TARGET"
traceroute -T -p 443 "$TARGET"

# 8) 超售与 steal（晚高峰跑）
mpstat -P ALL 1 5
top -bn1 | head -5
cat /proc/pressure/cpu 2>/dev/null

# 9) 晚高峰连续采样：每 5 分钟一次，共 30 次
for i in $(seq 1 30); do
  date +%H:%M
  ping -c 20 "$TARGET" | tail -2
  curl -s -o /dev/null -w "down=%{speed_download} B/s\n" \
    "https://speed.cloudflare.com/__down?bytes=10000000"
  sleep 300
done
```

两个单位换算记住：`curl` 输出是 B/s，乘 8 除以 1e6 才是 Mbps；`iperf3` 输出已经是 Mbits/sec，除以 8 才是 MB/s。

每维按 0–5 分打，`得分 = 得分 ÷ 5 × 权重`，六项权重合计 100。这张表回答“这台机器值几分”；表下第 3 条说明怎么把分数变成结论。

| 项目 | 权重 | 实测（填这里） | 得分 | 判定 |
|---|---:|---|---:|---|
| 硬件 | 20 | 虚拟化类型 / CPU 代际 / 盘型 / 通电小时 |  | 5 分：型号对得上、通电 <2 万小时；3 分：一项存疑；1 分：多项对不上或洋垃圾 |
| 性能 | 25 | 单核 events/s / 4K IOPS / 双线程比 |  | 5 分：接近同代独服；3 分：低 20–40%；1 分：低一半以上或抖动剧烈 |
| 网络 | 25 | 晚高峰达成率 / 丢包 / 回程 |  | 5 分：≥80% 标称且丢包 <1%；3 分：50–80%；1 分：<30% 或丢包 >5% |
| IP | 15 | 独立 / 共享 / NAT / 动态 + 信誉分 |  | 5 分：独立且 whois 与宣传一致；3 分：独立但归属存疑；1 分：NAT 或脏 IP |
| 合规 | 10 | 主体 / 许可证 / 发票 / 备案 |  | 5 分：有证可开票；3 分：挂靠或部分可开；1 分：无证无票 |
| 服务 | 5 | 工单首响 / 退款条款 / 快照能力 |  | 5 分：24 小时内响应且有退款窗口；1 分：只靠群聊、不退款 |
| **合计** | **100** | — |  | — |

**示例（示意数据，不是实测）**：一台 2C2G、138 元/年的 B 档机器，硬件 3 分（12）、性能 4 分（20）、网络 3 分（15）、IP 4 分（12）、合规 2 分（4）、服务 4 分（4），合计 **67 分** → 仅玩具。注意它的价格维并不差，扣分全在“查不到许可证”和“晚高峰只跑到标称的 75%”上。

### 产出 3｜三条结论线

| 总分 | 结论 | 处理方式 |
|---|---|---|
| ≥ 80 | **可用** | 可以放非核心业务：展示站、小工具、海外访问入口。仍需异地备份 + 续费价进预算 |
| 60–79 | **仅玩具** | 只放可丢弃的东西：学习环境、临时演示、镜像站。不放用户数据、不放唯一副本、不备案 |
| < 60 | **退货或弃用** | 还在退款窗口就退；退不了就停止放数据，只留作一次性实验，到期不续 |

三条补充规则：

1. **一票否决**：查不到经营主体 + 只收年付 + 无发票 + 拒绝退款，四条同时命中，直接按 <60 处理，不用算分。
2. **双轨取严**：最终结论取“总分结论”和“价格结论”里更差的那个。分数 85 但价格只有 C 档地板的 0.4 倍，仍要降级。
3. **分数不是目的**：60 分和 79 分都是“仅玩具”，差别只在你还愿不愿意继续折腾。别为了多 5 分反复测速。

### 产出 4｜价格对照：被体检机在哪个档

先把年价放进三档地板里对齐（2C2G 基准，年地板取自三档模型：A 600 / B 180 / C 36）。

| 被体检机年价 | 对 A 地板 600 | 对 B 地板 180 | 对 C 地板 36 | 读法 |
|---:|---:|---:|---:|---|
| 600 元/年 | 1.00 | 3.3 | 16.7 | 贴着 A 档地板，价格合理，看服务与合规 |
| 408 元/年 | 0.68 | 2.3 | 11.3 | B 档精品线路常见价（快照 P-013，2026-11），要验线路真假 |
| 180 元/年 | 0.30 | 1.00 | 5.0 | 正好踩 B 档地板，可持续但一定有妥协 |
| 138 元/年 | 0.23 | 0.77 | 3.8 | 略低于 B 档地板（快照 P-011，2026-11），超售是必然项 |
| 104 元/年 | 0.17 | 0.58 | 2.9 | 跨档价：对 C 档像绿灯，对 B 档是红灯（快照 P-018，2026-11） |
| 72 元/年 | 0.12 | 0.40 | 2.0 | 1C1G 促销价（快照 P-017，2026-11）；配置低一档，比值只作参考 |
| 36 元/年 | 0.06 | 0.20 | 1.00 | 正好是 C 档地板，任何一项“独享”承诺都不成立 |

**“价格低于地板”到底意味着什么**：不是“一定是骗局”，而是“至少有一项成本被转移了”。可选解释只有五种——补贴、超售、NAT/共享 IP、达量限速、跑路。体检的作用就是指出是哪一种：

- `%steal` 高、晚高峰掉速 → **超售**。
- 网卡是内网地址、端口要手动映射 → **NAT/共享 IP**。
- 白天正常、跑满 100GB 后限到 1Mbps → **限速**。
- 首年 30 元、续费 300 元 → **补贴**，第 2 年补回来。
- 主体查不到、只收年付、客服失联 → **跑路风险**。

再补一个单看 IP 的算法：一个独立 IPv4 的批发租用价约 3.0–4.3 元/月，折合 36–52 元/年（快照 P-027，2026-11）；一线城市零售加 1 个 IP 约 60 元/月或 700 元/年（快照 P-032，2026-11）。也就是说，**年费 36 元的机器，光一个独立 IP 的批发成本就吃掉了全部收入**，电、带宽、运维还没算。所以这个价位要么是 NAT/共享 IP，要么是补贴，二者必居其一。

## 常见问题

**1. `smartctl` 提示 Permission denied 或找不到设备。**
先确认装了 `smartmontools` 并用 `sudo` 跑；再用 `lsblk` 找真实设备名（`/dev/sda`、`/dev/vda`、`/dev/nvme0` 都可能）。KVM 的 virtio 盘经常不透传 SMART，这是平台限制，不是你的操作问题——记录“读不到”，改用 IOPS 和通电表现间接判断。

**2. 机器是 OpenVZ/LXC，完全读不到 SMART。**
`systemd-detect-virt` 返回 `openvz` 或 `lxc`，说明是共享内核，没有独立块设备。这类机器的 CPU、内存、磁盘数据都会被邻居影响，体检结论要打折扣：所有性能项按“仅参考”记录，重点看 IP 形态、网络与合规。OpenVZ 还可以看 `cat /proc/user_beancounters` 里的资源上限。

**3. 晚高峰我人在上班，测不了。**
把采样挂到机器上跑，不要依赖你在线。用步骤 10 的循环配合 `tmux`，第二天收数据。没有对端机器时，用 `ping` + 小文件 `curl` 就够判断趋势，别用 `iperf3`——它最费流量，也最容易被 QoS 针对。

**4. 怀疑 IP 被墙了，怎么确认？**
分别从境内和境外各 `ping` 一次、各 `nc -vz <IP> 443` 一次。境外通、境内不通，且换端口仍不通，基本可以判被墙。再用多地 ping 平台对比一遍。被墙属于 IP 层面的问题，换系统、换端口都没用，只能换 IP 或放弃这台机器。

**5. 磁盘测试会不会写坏数据？**
`fio` 会真实写文件，确实有风险。三条纪律：只在空目录跑、`--size` 不超过可用空间的一半、绝不在挂载业务数据的分区跑。跑之前 `df -h` 记一次，跑完 `rm` 再 `df -h` 核一次。生产机直接跳过步骤 6，用 `dd` 读测试代替。

**6. 测速结果一次 200M、一次 40M，波动太大。**
单次测速没有意义。固定对端、固定时段、固定并发，连测 5 次取中位数；同时区分 Mbps 与 MB/s，别把 40MB/s 当成 40Mbps。共享带宽本来就抖，看的是“晚高峰相对凌晨的比例”，不是某一次的峰值。

**7. `fio` 报 `libaio` 找不到。**
装 `libaio1`；装不上就把 `--ioengine=libaio` 换成 `--ioengine=psync`。`psync` 的结果偏低，但同一台机器前后对比仍然有效，报告里注明引擎类型即可。

**8. `iperf3` 连不上对端。**
先确认对端 `iperf3 -s` 在跑、防火墙放了 5201 端口；再确认你没连到公共测速节点上被人限速。公共节点只能作参考，不能当验收依据。

## 安全提示

- **只测自己的机器**。扫描、压测、大流量打别人的地址，既是技术问题也是法律问题。`iperf3` 的服务端必须是你自己的。
- **`fio` 和 `dd` 会写文件**。跑之前看清楚路径，跑完立刻删；不要在系统盘根目录、数据盘、数据库目录里跑。
- **别在生产盘上做体检**。要体检就先做快照，或在业务低峰、可停机的时间窗内做。
- **测完清理**：`rm -f /root/lab6/randrw /root/lab6/seqread`，再 `df -h` 确认空间回来了。测试文件留在盘上，既占空间也泄露你的测试习惯。
- **不要用主账号**。独立邮箱、独立密码、独立支付方式；不开自动续费；不在机器上放主账号的 AccessKey、支付信息、其他业务密码。
- **不要把 IP、密钥、控制台截图原文发到公开仓库或群聊**。报告里要引用就脱敏，写成 `<你的服务器IP>`。
- **控制台操作先看清计费**。快照、备份、镜像、额外 IP 都可能单独计费，点“创建”之前先看单价。
- **遵守服务商条款**。长期跑满带宽、开公共代理、做扫描节点，都可能触发封禁；体检用的流量控制在合理量级。

## 完成后你应该得到什么

一份 `lab6-report.md`，包含：

1. **一张体检表**：13 项实测值，每项都有对应的证据文件。
