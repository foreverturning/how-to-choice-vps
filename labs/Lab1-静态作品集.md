# Lab 1 静态作品集：0 元部署到免费静态托管

> 做完你会得到：一个能用 HTTPS 打开的公开网址；一条从本地到线上的可复现部署流程；一份写清免费额度与到期日的记录。
> 对应总纲：Lab 1 ｜ 对应文章：[02 算账篇](../chapters/02-算账篇.md) 的 2.2、[03 白嫖篇](../chapters/03-白嫖篇.md) 的 3.4 ｜ 预计耗时：40–90 分钟（不含域名生效等待）

## 目标

把一个纯静态作品集（手写 HTML/CSS/JS，或 Vite 类工具的构建产物）部署到免费静态托管上，全程不买服务器、不买带宽，托管费用 0 元。

完成后你要能回答三个问题：

1. 我的项目为什么不需要服务器？（因为页面不在服务器上“跑”，文件由 CDN 直接发出去）
2. 这条流水线里哪一步会花钱？（只有自定义域名；托管本身 0 元）
3. 免费额度用完了会怎样？（多数是限流或要求升级，不是悄悄扣费）

这条路对应 02 的场景 A：静态页、作品集、落地页，月成本 0 元。托管侧的额度口径是静态请求不限、动态函数 10 万次/日（快照 P-022，2026-11）。

## 前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| 作品集代码 | 纯前端，无服务端逻辑 | 页面里调第三方公开接口仍算静态；一旦要藏密钥、写数据库，请转 [Lab 2](./Lab2-全栈小工具.md) |
| Node.js | 18 及以上，附 npm | 只有需要构建（Vite/React 等）时才必需；纯 HTML 可跳过 |
| Git | 任意近期版本 | 用来把代码推到代码托管平台 |
| 代码托管账号 | 一个（GitHub 类） | 建议单独注册，不复用主账号 |
| 静态托管账号 | 一个（Pages 类） | 免费层即可，额度见快照 P-022 |
| 终端 | PowerShell / Terminal / WSL 任一 | 下文命令以 bash 语法为主，PowerShell 差异处已注明 |
| 自有域名 | 可选 | 不买也能上线，平台会给一个默认子域名 |

开始前先做一件事：把项目里所有 `.env`、密钥、内网地址找出来，确认它们不会被提交。这一步比后面任何一步都重要。

## 步骤

### 步骤 1｜确认项目是纯静态的

- **做什么**：逐个打开源码，搜 `API_KEY`、`SECRET`、`TOKEN`、`DATABASE_URL`。凡是需要“服务器替你先保管一把钥匙”的功能，都不属于本 Lab。
- **在哪做**：本机项目目录，编辑器全局搜索。
- **成功标志**：搜不到任何真实密钥；若搜到，先改成“从构建环境变量读取”，并确认该变量本身不是敏感值。

### 步骤 2｜本地先跑通

- **做什么**：用静态文件服务器在本地打开页面，确认首页、样式、图片、跳转都正常。
- **在哪做**：本机项目根目录。
- **成功标志**：浏览器访问 `http://localhost:3000`，控制台（F12）没有红色报错，图片没有裂图。

### 步骤 3｜构建并确认输出目录

- **做什么**：执行构建，然后打开产物目录看一眼里面是不是有 `index.html`。
- **在哪做**：本机项目根目录。
- **成功标志**：终端出现 “build completed” 一类提示，且 `dist/`（或 `build/`、`out/`、`public/`）里确实有 `index.html`。记下这个目录名，步骤 7 要用。

### 步骤 4｜初始化 Git 仓库并写 .gitignore

- **做什么**：`git init`，创建 `.gitignore`，把依赖目录、构建产物、环境变量文件排除掉。
- **在哪做**：本机项目根目录。
- **成功标志**：`git status` 里看不到 `node_modules/`、`.env`、`dist/`。若 `.env` 已经出现在列表里，先补 `.gitignore` 再继续。

### 步骤 5｜提交并推送到代码托管平台

- **做什么**：提交代码，在平台上新建一个**公开或私有**仓库，把本地仓库推上去。
- **在哪做**：本机 + 代码托管平台网页端。
- **成功标志**：刷新仓库页面能看到 `index.html` 与 `package.json`；仓库里搜不到 `.env`。

### 步骤 6｜在托管平台导入仓库

- **做什么**：登录静态托管控制台，选择“从 Git 仓库导入”，授权平台读取这一个仓库。
- **在哪做**：托管平台控制台。
- **成功标志**：仓库出现在项目列表里；授权范围只勾了目标仓库，没有给全账号权限。

### 步骤 7｜填写构建命令与输出目录

- **做什么**：按项目实际情况填三条：构建命令（`npm run build` 或留空）、输出目录（步骤 3 记下的那个）、Node 版本。环境变量只填**非敏感**的配置项。
- **在哪做**：托管平台的项目设置页。
- **成功标志**：设置页保存成功，预览区显示“等待首次部署”。

### 步骤 8｜触发首次部署并验证

- **做什么**：点部署，等流水线跑完，拿到平台分配的默认域名，用 `curl` 请求一次。
- **在哪做**：托管平台控制台 + 本机终端。
- **成功标志**：部署日志最后一行是成功；`curl -I` 返回 `HTTP/2 200`，且 `content-type` 是 `text/html`。若返回 404，先看步骤 7 的输出目录。

### 步骤 9｜做一轮冒烟测试

- **做什么**：用手机流量、浏览器无痕窗口各打开一次；再直接访问一个内页地址并刷新。
- **在哪做**：手机 + 电脑浏览器。
- **成功标志**：首屏 3 秒内出现内容；内页刷新不出现 404（若出现，按“常见问题 2”处理）；控制台无报错。

### 步骤 10｜绑定自定义域名（会产生费用）

> ⚠️ 会产生费用：域名注册通常几十元/年（待核对，按注册商当年报价），托管侧不额外收费。这一步可以跳过，跳过不影响前面所有产出。

- **做什么**：在托管平台添加域名，平台会给一条 DNS 记录（子域名通常是 `CNAME`，根域名是 `A`/`ALIAS` 或要求改用平台名称服务器）；到域名注册商的 DNS 面板照抄添加，需要验证时再补一条 `TXT`。
- **在哪做**：托管平台“自定义域名”页 + 域名注册商 DNS 控制台。
- **成功标志**：`dig +short <你的域名>` 能返回平台给出的目标地址；平台域名状态从“待验证”变成“有效”。生效时间通常是几分钟到几小时，受 TTL 与递归缓存影响，慢的时候按 24 小时预期。

### 步骤 11｜开启 HTTPS 并强制跳转

- **做什么**：在平台侧开启自动证书与“强制 HTTPS”。证书由平台签发，不需要你手动上传。
- **在哪做**：托管平台的域名/SSL 设置页。
- **成功标志**：`https://<你的域名>` 能打开且地址栏是小锁；访问 `http://` 版本会 301 跳到 `https://`；证书签发状态为“已激活”。

### 步骤 12｜登记额度与到期日

- **做什么**：把平台、套餐、额度、重置周期、域名到期日写进一张表，放进仓库 README 或你的到期日历。
- **在哪做**：本机仓库 + 你的日历工具。
- **成功标志**：下个月你能凭这张表说清“这个站每个月有多少额度、什么时候到期、超了会怎样”。

## 命令

### 本地预览与构建

```bash
# 纯 HTML 项目：任选一种本地服务器
python -m http.server 3000
npx --yes serve . -l 3000

# 有构建步骤的项目
npm ci
npm run build
ls dist | head
```

### Git 初始化与推送

```bash
git init
printf 'node_modules/\ndist/\n.env\n.env.*\n.DS_Store\n' > .gitignore
git add .
git commit -m "chore: init static portfolio"
git branch -M main
git remote add origin https://github.com/<你的账号>/<你的仓库>.git
git push -u origin main
```

PowerShell 下 `printf` 不可用，改用：

```powershell
"node_modules/`ndist/`n.env`n.env.*`n.DS_Store" | Out-File -Encoding utf8 .gitignore
```

### 部署后验证

```bash
curl -I https://<平台默认域名>
curl -s -o /dev/null -w "%{http_code}\n" https://<平台默认域名>
curl -s https://<平台默认域名> | grep -o "<title>.*</title>"
```

### 域名与 HTTPS 验证

```bash
dig +short <你的域名>
dig +short www.<你的域名>
curl -I http://<你的域名>
curl -sI https://<你的域名> | grep -i "strict-transport-security"
```

## 常见问题

### 1. 部署成功但打开是 404 或白屏

八成是输出目录填错。平台默认去仓库根目录找 `index.html`，而 Vite 类项目的产物在 `dist/`。回到步骤 7，把输出目录改成实际目录名再重新部署。白屏但状态码 200，多半是资源路径写成了硬编码路径，检查构建配置里的 `base`。

### 2. 首页能开，刷新内页就 404

这是单页应用（SPA）的典型问题：路由在前端跳转，服务器上并不存在 `/about` 这个文件。处理方式是在托管平台加一条回退规则，把所有未命中的路径重写到 `/index.html`；部分平台在设置里直接叫 “SPA 模式” 或 “Rewrite all to index.html”。改完记得再刷新一次验证。

### 3. 环境变量不生效

前端项目的环境变量是**构建时**写进代码的，不是运行时读取的。三个检查点：变量名是否带框架要求的前缀（如 `VITE_`）；改完变量后有没有重新部署；变量是不是填在了“运行时”而不是“构建时”的位置。另外记住：任何进了前端的环境变量都等于公开，只能放非敏感配置。

### 4. 会不会突然开始收费

免费静态托管的额度口径是静态请求不限、动态函数 10 万次/日，超限是要求升级而不是扣费（快照 P-022，2026-11）。如果你用的是 Hobby 类前端托管，额度是 100GB/月、100 万次函数调用/月，超量是限流，但**免费版禁止商用**（快照 P-023，2026-11），要商用得升到约 $20/月。对策：开用量告警，把“这个站是否商用”写进额度表。

### 5. 域名加了但一直不生效

按顺序查四件事：记录类型对不对（根域名多数平台不支持 `CNAME`，要用 `A`/`ALIAS`）；主机记录有没有多写或漏写 `www`；有没有和旧的 `A` 记录冲突（同一个名字两条记录会互相打架）；TTL 是不是设得很长。用 `dig +short` 直接问权威 DNS，比在浏览器里反复刷新可靠。

### 6. 国内访问很慢

免费托管的节点多在境外，国内打开慢是线路问题，不是配置问题。可以先用默认域名确认功能正常，再决定要不要为国内访问速度换方案（换方案通常意味着要备案和买机器，见 [Lab 3](./Lab3-轻量服务器建站.md)）。别把“慢”误判成“部署失败”。

### 7. 构建在平台上失败，本地却正常

先看日志里第一行报错。常见原因：平台默认 Node 版本低于项目要求（在设置里指定版本）；本地是 Windows、平台是 Linux，文件名大小写不一致导致找不到文件；`package-lock.json` 没提交，依赖版本漂移。修完推一次提交即可重新触发。

## 安全提示

1. **不要把密钥写进前端。** 构建产物是公开文件，任何人按 F12 都能看到源码里的字符串。前端只放“公开的配置”，密钥留在服务端，这也是本 Lab 只做静态站的边界。
2. **不要提交 `.env`。** 先写 `.gitignore` 再 `git add`。如果已经提交过，删文件不等于删历史，需要清理提交历史并**轮换那把密钥**——假定它已经泄露。
3. **演示站不要收集个人信息。** 作品集里的联系表单如果要收姓名、手机号、住址，就别用免费静态站硬扛：要么改成 `mailto:` 链接，要么用第三方表单服务并写明用途。简历里不写身份证号、家庭住址、真实门牌。
4. **账号隔离。** 托管平台与代码托管平台都用独立账号注册，只授权目标仓库，不给组织管理员权限。不要用主邮箱做主登录。
5. **第三方脚本要克制。** 统计、字体、客服挂件都是外部代码，会拿到你页面的访问数据。只留必要的，其余删掉。
6. **公开仓库里不留内部信息。** 服务器 IP、内网地址、数据库连接串、同事邮箱，都不该出现在示例配置里。

## 完成后你应该得到什么

- 一个 `https://` 开头的公开网址，能在手机和电脑上正常打开，刷新内页不 404。
- 一条可复现的部署链路：改代码 → 提交 → 推送 → 平台自动构建 → 线上更新。下次换项目，照步骤 4 到 8 再走一遍即可。
- 一份额度表：写清了套餐、月额度、重置周期、超限后果、域名到期日。这张表就是 [03 白嫖篇](../chapters/03-白嫖篇.md) 里“到期日历”的第一行。
- 一个成本结论：这个站的托管费用是 0 元，唯一可能花钱的是域名。把它填进 [02 算账篇](../chapters/02-算账篇.md) 的场景 A 成本卡，你的第一张成本表就有了一行真实数据。
- 一条判断力：你现在能分清“静态托管”和“买一台服务器”的区别，也就知道了为什么 02 篇说“给自行车买柴油”。
