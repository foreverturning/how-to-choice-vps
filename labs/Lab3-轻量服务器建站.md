# Lab 3 轻量服务器建站：从下单到域名 HTTPS 访问

> 做完你会得到：一台自己维护的国内轻量服务器；一个用域名 + HTTPS 打开的站点；一份可复用的安全基线与快照记录。
> 对应总纲：Lab 3 ｜ 对应文章：[06 选型篇](../chapters/06-选型篇.md) 的 6.2 ｜ 预计耗时：2–4 小时（不含备案审核与 DNS 生效等待）

---

## 目标

买一台国内轻量应用服务器（2 核 2G，3–4M 带宽），把一台“刚付款的空机器”变成“域名能 HTTPS 访问的站点”，并在此过程中建立一套最低限度的安全基线。

选择轻量而不是 ECS/CVM，理由在 [06 选型篇](../chapters/06-选型篇.md) 的 6.2 已经算过：新手项目九成是单机、低流量、不需要组网，轻量把 CPU、内存、系统盘、带宽、流量打包成一个价，ECS 则是逐项计价的积木。同配置下，轻量套餐首年约 99–300 元/年（快照 P-003、P-004、P-006，2026-11），而 ECS 单买 5M 固定带宽按目录价就是 125 元/月（快照 P-031，2026-11）。本 Lab 只做单机建站，不涉及负载均衡、云数据库、对象存储。

完成后你要能回答四个问题：

1. 从付款到能访问，中间到底有哪几道关？（安全组、系统防火墙、Nginx 监听、DNS、证书，缺一不可）
2. 为什么“买完就有网站”是错觉？（备案、解析、证书都是独立步骤，不会自动完成）
3. 哪些步骤会产生费用，量级多少？
4. 一台刚上线的机器，最少要做哪五件安全事？

## 前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| 云账号 | 一个已完成实名认证的账号 | 国内地域购买与备案都要求实名；建议单独注册账号做实验，不绑主业务 |
| 支付方式 | 可付款的渠道 | 先月付，别一上来年付 |
| 自有域名 | 一个已注册的域名 | 域名几十元/年（待核对），注册后需完成域名实名认证 |
| 本地终端 | Windows PowerShell / macOS Terminal / Linux shell | 需要 `ssh`、`ssh-keygen`、`scp`；Windows 10 以上自带 OpenSSH |
| 站点文件 | 一个 `index.html` 起步即可 | 静态页最省事；带后端的项目本 Lab 不展开 |
| 备案 | 国内地域必须先备案 | 详见下文“备案说明”一节；境外地域免备案 |
| 时间 | 2–4 小时，另加 DNS 与备案等待 | 备案通常需要数个工作日到数周，别卡在上线前一天才办 |

开始前先明确一件事：**备案不是买完服务器自动就有的**。国内地域的域名要对外提供网站服务，必须走 ICP 备案；没有备案，解析到国内 IP 的 80/443 通常会被拦截。这一步的时间成本远大于技术成本，先办。

## 步骤

### 步骤 1｜选配置与地域（会产生费用）

- **做什么**：在控制台选“轻量应用服务器”，配置 2 核 2G、系统盘 40–50G、带宽 3–4M，地域选离你用户最近的中国内地地域。镜像选 Ubuntu 22.04 或 24.04 LTS。
- **在哪做**：云厂商控制台的轻量产品页。
- **成功标志**：购物车/订单页显示的配置与价格符合预期，且明确标注“续费价”。首年价是获客补贴，续费价才是真实价格；同配置轻量首年约 99–300 元/年，续费可能回到 300–800 元/年（快照 P-003、P-004、P-006，2026-11）。
- **判断要点**：地域决定三件事——是否需要备案、到用户的延迟、以及有没有货。国内地域要备案；境外地域免备案，但回国访问要绕线路，晚高峰延迟和丢包另算。若你只是给自己看、不涉及备案，境外轻量也是选项（快照 P-009，2026-11）。

### 步骤 2｜下单，先月付（会产生费用）

- **做什么**：计费周期选“1 个月”，不要选 1 年或 3 年。付款前把商品页的“带宽/流量/达量限速/退款规则”四项截图存档。
- **在哪做**：订单确认页。
- **成功标志**：订单支付成功，控制台出现一台“运行中”的实例，并给出公网 IP。
- **为什么先月付**：这是 06 与 07 反复强调的纪律——先月付跑通，再决定是否年付。月付多花的那点钱，是买“可以反悔”的权利。付款后立刻在账单页设置预算告警（见 [Lab 5 预算告警与复盘](./Lab5-预算告警与复盘.md)）。

### 步骤 3｜配置安全组（只开 22 / 80 / 443）

- **做什么**：在轻量控制台找到“防火墙/安全组”，默认规则全删或收紧，只保留三条入方向规则：TCP 22（SSH）、TCP 80（HTTP）、TCP 443（HTTPS）。出方向保持默认全放通。
- **在哪做**：轻量实例详情页 → 防火墙。
- **成功标志**：入方向只有 22、80、443 三条，来源写 `0.0.0.0/0`（22 建议先临时限制为你自己的出口 IP，跑通后再放开或保留限制）。
- **常见坑**：控制台安全组和系统内防火墙是两道独立的门，只开一道等于没开。步骤 9 会配第二道。

### 步骤 4｜准备登录凭证：密钥对或重置密码

- **做什么**：二选一。优先在购买时选择“密钥对”，没有则用控制台“重置密码”设一个 16 位以上、含大小写与符号的随机密码，仅用于首次登录。
- **在哪做**：控制台实例详情 → 密钥/密码；密钥对在“密钥管理”里创建并下载私钥。
- **成功标志**：本地保存了私钥文件（如 `lab3_ed25519`），或记住了刚重置的临时密码。
- **注意**：私钥文件权限必须是 600，Windows 下放在用户目录而非共享盘；私钥只此一份，丢了只能重建。临时密码用完即弃，步骤 8 会关闭密码登录。

### 步骤 5｜首次 SSH 登录

- **做什么**：从本地终端用密钥或密码登录服务器，确认能进系统、能联网。
- **在哪做**：本地终端。
- **成功标志**：提示符变成 `root@<主机名>`，`curl -I https://www.baidu.com` 返回 `200` 说明出网正常。
- **首次登录先做一件事**：`cat /etc/os-release` 确认系统版本与镜像一致，避免买到与商品页不符的系统。

### 步骤 6｜系统更新并开启自动安全更新

- **做什么**：更新软件索引、升级已安装包、安装并启用 `unattended-upgrades`。
- **在哪做**：服务器上，root 或 sudo 用户。
- **成功标志**：`apt upgrade` 无报错结束；`systemctl status unattended-upgrades` 显示 `active (running)`。
- **注意**：升级内核后需要重启才生效，重启前确认没有正在跑的长任务。自动更新只装安全补丁，不建议开启自动重启，避免站点半夜自己重启。

### 步骤 7｜创建普通用户并授予 sudo

- **做什么**：新建 `deploy` 用户，加入 `sudo` 组，把 root 的 `authorized_keys` 复制过去。
- **在哪做**：服务器上，仍以 root 操作。
- **成功标志**：`id deploy` 输出里含 `sudo` 组；`/home/deploy/.ssh/authorized_keys` 存在且属主是 `deploy`，权限 600。
- **为什么**：长期用 root 是运维事故的第一大来源。普通用户 + sudo，至少留下一条“谁在什么时候做了什么”的痕迹，也能降低误删系统文件后无法恢复的概率。

### 步骤 8｜验证普通用户登录，再禁用 root 密码登录

- **做什么**：**先**另开一个终端，用 `deploy` 用户 + 密钥登录成功；**再**写 SSH 加固配置，关闭 root 登录与密码登录，最后 reload sshd。
- **在哪做**：本地新终端（验证）+ 服务器（改配置）。
- **成功标志**：新终端能登录；`sshd -t` 无输出（语法正确）；`sshd -T | grep -E "permitrootlogin|passwordauthentication"` 显示 `no` / `no`。
- **顺序不能反**：先确认新通道可用，再关旧通道。反了就是把自己锁在门外，只能去控制台开 VNC 救援。

### 步骤 9｜配置主机防火墙 ufw

- **做什么**：放行 OpenSSH、80、443，然后启用 ufw，查看规则。
- **在哪做**：服务器上，sudo 用户。
- **成功标志**：`ufw status verbose` 显示 `Status: active`，且只有 22/80/443 三条 allow。
- **注意**：启用前务必确认 22 已放行，否则当前 SSH 会话断开后就连不上了。云厂商镜像有时预装 firewalld，先确认没有两套防火墙打架。

### 步骤 10｜安装 Nginx 并设为开机自启

- **做什么**：安装 Nginx，启动并设置开机自启，确认监听 80。
- **在哪做**：服务器上。
- **成功标志**：`systemctl is-enabled nginx` 输出 `enabled`；`ss -lntp | grep :80` 能看到 nginx 进程；浏览器访问 `http://<你的服务器IP>` 出现 Nginx 默认欢迎页。
- **说明**：此时还没有域名和证书，先用 IP 验证“Web 服务活着”。如果 IP 打不开，先查安全组与 ufw，不要急着装证书。

### 步骤 11｜放站点文件并配置 Nginx 站点

- **做什么**：建 `/var/www/<你的域名>` 目录，放入 `index.html`；新建站点配置文件，`server_name` 写你的域名，root 指向该目录；启用站点并删掉默认站点；`nginx -t` 通过后 reload。
- **在哪做**：本地（传文件）+ 服务器（配置）。
- **成功标志**：`nginx -t` 输出 `syntax is ok` 与 `test is successful`；`curl -I http://<你的服务器IP> -H "Host: <你的域名>"` 返回 200。
- **权限要点**：目录属主 `www-data:www-data`，目录 755、文件 644。不要图省事 `chmod 777`，那等于给所有人写权限。

### 步骤 12｜解析域名（会产生费用）

- **做什么**：在域名服务商的 DNS 控制台添加两条 A 记录：主机记录 `@` 和 `www`，值都指向服务器公网 IP，TTL 先设 600 秒。
- **在哪做**：域名注册商/ DNS 服务商控制台。
- **成功标志**：`dig +short <你的域名>` 与 `dig +short www.<你的域名>` 都返回你的服务器 IP。
- **费用**：域名几十元/年（待核对），续费价通常高于首年；DNS 解析本身一般免费。
- **注意**：域名必须先完成实名认证，否则解析会被暂停。若使用带代理的 CDN（橙色云朵），先关掉代理再申请证书，否则 HTTP-01 校验会被挡。

### 步骤 13｜申请 Let's Encrypt 证书（0 元）

- **做什么**：安装 certbot 与 nginx 插件，执行 `certbot --nginx -d <你的域名> -d www.<你的域名>`，按提示选“重定向 HTTP 到 HTTPS”。
- **在哪做**：服务器上。
- **成功标志**：`/etc/letsencrypt/live/<你的域名>/fullchain.pem` 存在；`certbot certificates` 显示有效期约 90 天。
- **为什么免费**：Let's Encrypt 走 ACME 协议自动签发，证书本身 0 元，代价是 90 天有效期，必须靠自动续期。商业 DV 证书与本 Lab 无关。

### 步骤 14｜强制 HTTPS 并确认自动续期

- **做什么**：确认 80 的请求返回 301 跳到 443；执行一次 `certbot renew --dry-run`；确认系统里有 certbot 的定时任务。
- **在哪做**：服务器上。
- **成功标志**：`curl -I http://<你的域名>` 返回 `301` 且 `Location` 是 `https://`；`--dry-run` 输出 `Congratulations, all simulated renewals succeeded`；`systemctl list-timers | grep certbot` 有下一次执行时间。
- **说明**：certbot 的 systemd timer 默认每天跑两次，只在到期前 30 天内才真正续。dry-run 成功不等于线上一定成功，上线一周后回来看一眼证书到期日。

### 步骤 15｜验证：从三个角度各测一次

- **做什么**：分别验证 HTTP 跳转、HTTPS 响应、证书链与域名一致性。
- **在哪做**：本地终端 + 浏览器。
- **成功标志**：
  - `curl -I http://<你的域名>` → 301
  - `curl -I https://<你的域名>` → 200，且响应头有 `strict-transport-security`（若你加了这个头）
  - 浏览器地址栏是小锁，点开证书，颁发者是 Let's Encrypt，域名匹配，有效期正确
  - 手机 4G 网络（不走公司 WiFi）也能打开，排除本地 DNS 缓存干扰

### 步骤 16｜打一个快照（可能产生费用）

- **做什么**：在控制台为系统盘创建快照，命名写清日期与用途，例如 `lab3-20261108-上线前`。
- **在哪做**：轻量实例详情 → 快照/备份。
- **成功标志**：快照状态为“可用”，记录里有创建时间与占用容量。
- **费用**：快照按占用容量计费，通常每月几元量级（待核对）；部分套餐含免费额度。相比重装系统重配一遍的时间，这笔钱值得花。
- **注意**：快照不是备份。同区域快照在账号或区域出问题时一起消失，重要数据仍要异地留一份。

## 备案说明（国内地域必读）

这一节单独写，因为它是国内建站最容易卡住、也最容易被教程一句带过的地方。

**结论：买服务器和能建站是两件事。国内地域的域名要对外提供网站服务，必须先完成 ICP 备案；备案不是购买后自动生成的，需要你主动提交材料并等审核。**

三件事要分清：

| 事项 | 谁来做 | 大概要多久 | 没做会怎样 |
|---|---|---|---|
| 域名实名认证 | 你在域名注册商处完成 | 1–3 个工作日 | 域名被暂停解析（serverHold） |
| ICP 备案 | 你在云厂商备案系统提交，厂商初审后转管局 | 数个工作日到数周 | 国内地域 80/443 被拦截，域名无法访问 |
| 公安联网备案 | 网站开通后按规定办理 | 以当地要求为准 | 视当地监管要求，可能被要求整改 |

备案的硬性前提，逐条核对：

1. 服务器必须是国内地域，且在你名下、在有效期内；境外地域（香港、新加坡、美国等）不需要 ICP 备案。
2. 域名持有人（实名信息）必须与备案主体一致；个人备案不能用公司域名，反之亦然。
3. 备案要填网站名称、服务内容、负责人信息，部分省份要求提供核验单或视频核验。
4. 备案通过后，网站底部要展示备案号并链接到工信部备案系统。
5. 换服务器、换主体、换域名都要做变更备案，不是一劳永逸。

境外地域的取舍：免备案，开通即用，但回国访问的线路质量差别很大。普通国际线路晚高峰可能绕路、丢包；带中国方向优化的线路贵一档（快照 P-019～P-021，2026-11）。如果用户主要在国内、又要长期正经运营，国内地域 + 备案仍是更稳的选择；如果只是自己看、做 Demo、给海外用户看，境外地域省掉的是时间而不是钱。

**一句话：先确认你能不能备案、愿不愿意等，再决定买哪个地域。** 顺序反了，机器只能闲置。

## 命令

以下命令按步骤分组，可直接复制。先把两个变量改成你自己的值，后续命令都用变量引用，避免手打出错。

```bash
export SERVER_IP="<你的服务器IP>"
export DOMAIN="<你的域名>"
```

**本地：生成密钥并首次登录（步骤 4–5）**

```bash
ssh-keygen -t ed25519 -C "lab3-deploy" -f ~/.ssh/lab3_ed25519
ssh -i ~/.ssh/lab3_ed25519 root@$SERVER_IP
```

**服务器：系统更新与自动安全更新（步骤 6）**

```bash
apt update
apt upgrade -y
apt install -y unattended-upgrades
dpkg-reconfigure -plow unattended-upgrades
systemctl status unattended-upgrades --no-pager
```

**服务器：创建普通用户并迁移公钥（步骤 7）**

```bash
adduser deploy
usermod -aG sudo deploy
mkdir -p /home/deploy/.ssh
cp /root/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys
```

**服务器：SSH 加固（步骤 8，先验证新用户能登录再执行）**

```bash
cat >/etc/ssh/sshd_config.d/99-lab3.conf <<'EOF'
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
EOF
sshd -t
systemctl reload ssh
sshd -T | grep -E "permitrootlogin|passwordauthentication"
```

**服务器：ufw 防火墙（步骤 9）**

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status verbose
```

**服务器：安装 Nginx（步骤 10）**

```bash
apt install -y nginx
systemctl enable --now nginx
systemctl is-enabled nginx
ss -lntp | grep :80
```

**服务器：站点目录与 Nginx 配置（步骤 11）**

```bash
mkdir -p /var/www/$DOMAIN
cat >/var/www/$DOMAIN/index.html <<'EOF'
<!doctype html>
<html lang="zh-CN">
<head><meta charset="utf-8"><title>Lab 3</title></head>
<body><h1>Lab 3 上线成功</h1><p>这台机器由我自己维护。</p></body>
</html>
EOF
chown -R www-data:www-data /var/www/$DOMAIN
find /var/www/$DOMAIN -type d -exec chmod 755 {} \;
find /var/www/$DOMAIN -type f -exec chmod 644 {} \;

cat >/etc/nginx/sites-available/$DOMAIN <<EOF
server {
    listen 80;
    listen [::]:80;
    server_name $DOMAIN www.$DOMAIN;
    root /var/www/$DOMAIN;
    index index.html;
    location / {
        try_files \$uri \$uri/ =404;
    }
}
EOF
ln -sf /etc/nginx/sites-available/$DOMAIN /etc/nginx/sites-enabled/$DOMAIN
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl reload nginx
```

**本地：传站点文件（可选，替换上面的示例页）**

```bash
scp -i ~/.ssh/lab3_ed25519 -r ./dist/* deploy@$SERVER_IP:/tmp/lab3-site/
ssh -i ~/.ssh/lab3_ed25519 deploy@$SERVER_IP \
  "sudo cp -r /tmp/lab3-site/. /var/www/$DOMAIN/ && sudo chown -R www-data:www-data /var/www/$DOMAIN"
```

说明：先传到 `/tmp` 再 `sudo cp`，是因为 `deploy` 用户对 `/var/www` 没有写权限；直接 scp 到站点目录会报 `Permission denied`。

**本地：验证 DNS（步骤 12）**

```bash
dig +short $DOMAIN
dig +short www.$DOMAIN
```

## 常见问题

**1. SSH 连不上，提示 `Connection timed out` 或 `Connection refused`**

先分清两种报错。`timed out` 多半是包被丢了：安全组没放行 22、ufw 拦了、或 IP 填错。`refused` 说明包到了机器但端口没监听：sshd 没启动，或你改了端口。排查顺序固定为：控制台 VNC 能否登录 → `systemctl status ssh` → `ss -lntp | grep :22` → 安全组规则 → ufw 规则。不要在本地反复重试，先确认服务器自己能不能连自己。

**2. 安全组开了还是访问不了**

两道门的问题：云控制台安全组是第一道，系统内 ufw/firewalld 是第二道。两道都要开。还有一种情况是安全组规则写了端口但协议选错（比如只放行 UDP），或者规则绑到了另一台实例。最后确认一次：`curl -I http://127.0.0.1` 在本机能通、公网不通，基本就是安全组或 ufw。

**3. 80 端口被占用，Nginx 起不来**

`Job for nginx.service failed` 多半是端口冲突。用 `ss -lntp | grep :80` 看谁占着。常见占用者：镜像预装的 Apache、另一个 Nginx 站点、宝塔类面板、docker-proxy。确认无用后 `systemctl disable --now apache2` 释放端口；若是另一个 Nginx 配置冲突，检查 `sites-enabled` 里是否有重复 `server_name`。改完必须 `nginx -t` 再 reload，不要直接 restart 掩盖错误。

**4. 证书申请失败**

certbot 的报错要看关键词：

- `Timeout during connect`：80 端口从公网不可达。查安全组、ufw、Nginx 是否监听 80。
- `Invalid response ... 404`：`/.well-known/acme-challenge/` 被你的 Nginx 配置或重写规则挡了。临时删掉自定义 rewrite 再试。
- `too many failed authorizations`：触发频率限制，等一段时间再用 `--dry-run` 调试。
- 域名用了 CDN 代理：先关闭代理（灰色云朵），证书签发后再开。
- `dns problem`：A 记录还没生效，或解析到了旧 IP。

**5. DNS 改了不生效**

先分清“没生效”和“生效了但本地缓存”。`dig +short <你的域名> @8.8.8.8` 和 `@223.5.5.5` 各查一次，两个公共 DNS 都返回新 IP，说明解析已生效，问题在你本地缓存或浏览器。Windows 用 `ipconfig /flushdns`，浏览器开无痕窗口。TTL 600 意味着最坏情况等 10 分钟；如果几小时还不对，检查是不是加错了记录类型（A 记录写成了 CNAME）、主机记录写成了完整域名、或者域名本身处于 serverHold（未实名）。

**6. 备案没通过 / 备案期间网站打不开**

先看驳回原因，常见四类：主体信息与域名实名不一致、网站名称不合规（含“中国”“官方”等敏感词）、服务内容描述与实际情况不符、负责人核验材料缺失。按驳回意见改，改完重新提交，不要重复提交同一份材料。备案审核期间，国内地域的域名访问会被拦截，这是正常现象，不是服务器坏了——此时用 IP 可以访问，说明机器本身没问题。境外地域不存在这一步。

**7. 浏览器提示“证书无效”或“连接不是私密连接”**

三种可能：证书过期（`certbot certificates` 看到期日）、域名与证书不匹配（只签了 `example.com` 却访问 `www.example.com`）、系统时间不对。自动续期失败最常见的原因是 80 端口后来被安全组关掉了——HTTP-01 校验需要 80 可达。每月花一分钟看一眼证书到期日，比出事后再救便宜。

**8. 站点返回 403 Forbidden**

九成是权限或索引文件问题。检查：`/var/www/<域名>/index.html` 是否存在；目录是否 755、文件是否 644；属主是否 `www-data`；Nginx 配置的 `root` 路径是否多写或少写一层目录。SELinux 开启的镜像还要看安全上下文，但 Ubuntu 默认不开。

## 安全提示

这五条是本 Lab 的底线，缺一条都不算“上线完成”。

1. **不要长期用 root**。创建普通用户 + sudo，root 只用于救援。长期 root 登录意味着一条命令就能毁掉整台机器，且日志里分不清是谁干的。
2. **不要用弱密码，也不要把密码登录留着**。SSH 暴露在公网，每天都有自动化爆破。用 ed25519 密钥，关掉 `PasswordAuthentication`；控制台重置的临时密码用完即弃。
3. **不要把私钥提交到仓库**。私钥不进 Git、不进网盘、不发群聊。`.gitignore` 里加 `*.pem`、`id_ed25519`、`.env`；一旦泄露，立刻在控制台删除该密钥对并重建。
4. **不要关闭防火墙图省事**。安全组只开 22/80/443，ufw 保持 active。为了装个面板而 `ufw disable`，等于把整台机器交给扫描器。需要新端口时，临时放行、用完删掉。
5. **上线前打快照，改配置前也打**。快照不能替代异地备份，但能把“重装重配两小时”压缩成“回滚十分钟”。改 Nginx、改 SSH、装新服务之前，各打一次。
6. **额外一条：不要把云账号主凭证放在服务器上**。这台机器只放站点文件，不放你的主账号 AccessKey、支付信息、其他业务数据库密码。服务器被攻破时，损失应止步于这台机器。
7. **预算告警与账单检查**。上线当天设置预算告警，第一周看一次流量与带宽曲线。轻量的“不限量”后面跟着达量限速条款（快照 P-001，2026-11），被刷流量时先限速、再排查来源。
