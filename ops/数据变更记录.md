## 二、裁决说明

- **只登记不裁决**：`UNK-01`~`UNK-50` 共 50 条冲突，A/B 两处官方口径并存，本台账不二选一、不写「以 X 为准」，处置列逐字「只登记，不裁决」。
- **UNK- 口径**：除两处官方口径冲突外，`UNK-` 同时承接「无官方明文」与「整类未覆盖 / 未穷举」，与 `appendix/来源清单.md` 字段说明同口径；新增此类登记按本节「复核写回不升版」处理，不占 `DC-`、不升 `data-version`。
- **复核写回不升版**：仅更新取证日期或复核状态、未改变 `S-` 数值时，不升 `data-version`。
- **升版触发**：涉及 `S-` 数值变化、新增或删除 `S-` 条目、`TERM-` 定义实质修改，须登记新 `DC-` 行并把版本 +1（`.1`、`.2`…）。
- **跨分册隔离**：vps 分册的价格编号、台账编号、成本模型在本分册 0 命中；两分支不做双向合并。
- **规则修订另走 `CR-`**：纯规则改动不占 `DC-`、不升 `data-version`，登记见第五节。

## 三、同步流程

1. 数据层变更 → 在本文件登记一行，`data-version` +1，写清旧值→新值与**受影响文档清单**。
2. 逐篇定点修复受影响文档；每篇完成后回填「同步状态 = 已同步」并写回执（回执人 + 日期 + `git diff` 校验方式）。
3. `git status --porcelain` 为空、且本台账无 `待同步` 项，才允许批次收尾。
4. 术语表只写定义与编号，不抄价格数值；来源清单只写 URL 与冲突登记；主报告只引 `S-`/`UNK-`/`TERM-` 编号。三者互不复制表格。
