> 版本口径：`data-version` 以 `YYYY-MM-DD.N` 递增；数据层变更必须版本 +1。
> 状态枚举：`待同步` / `已同步` / `主动不同步（并存口径）` / `历史遗留`
> 回执字段：回执人 + 日期 + `git diff` 校验方式

## 二、裁决说明

- **D-001 点名口径**：`_shared/写作规范.md` 5.1 的「头部公有云作出处可点名」是**出处层例外**；`00-总纲.md` :55 与 `_shared/价格快照-2026-11.md` :7,:164 的「不点名」是**正文/消费者层主线**。二者不真冲突，冲突来自未写明层级。裁决：不改主线、不改快照点名政策，仅在总纲 :55 补出处层指引；`chapters/03-白嫖篇.md` 按 QA 方案 A 去品牌化。
- **D-003 / D-005**：模型曾写「S2 未生成」，但快照已完整落地，属更新前状态残留；本次清理措辞，剩余差异转 D-005 长期跟踪，不再把整体标为待办。
- **D-006**：`appendix/A-F-附录.md` 已明确「统一采用成本模型口径，10.3 不再回改其数字」，属**主动不同步**，不纳入同步清单；两边均标注为教学示意口径。
- **D-008**：两处悬空是规范文档里的**示例文本**（写的是 `chapters/` 语境的相对路径），不是正文交叉引用，按灰区 G6 备案、不修改、不判缺陷。

## 三、同步流程

1. 数据层变更 → 在本文件登记一行，`data-version` +1，写清旧值→新值与**受影响文档清单**。
2. 逐篇定点修复受影响文档；每篇完成后回填「同步状态 = 已同步」并写回执（回执人 + 日期 + `git diff` 校验方式）。
3. `git status --porcelain` 为空、且本台账无 `待同步` 项，才允许批次收尾。
4. 派生层（`toolkit/**`、`appendix/**`）本次 P7 只按文件名登记到「受影响文档清单」，不加全量来源戳。
