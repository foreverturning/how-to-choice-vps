## 4. 每文件闸门

1. 路径存在；
2. 字符数 ≥ 目标字数 × 60%；
3. 标题层级与任务卡一致；
4. 无整节 `TODO`；
5. 含免责声明（章节/附录）；
6. `git add -- <精确路径> ops/进度.md`；
7. `git commit -m "<前缀>(<id>): <说明>"`。

前缀：`draft(shared|ch01..08|lab1..6|toolkit01..05|appendix)`、`fix(...)`、`qa(p7)`。

## 5. 批次收尾

1. 生成 `ops/commits.tsv`（文件 ↔ sha）；
2. 提交 `chore(ops): 记录 Pn`；
3. `git tag batch-pn`；
4. `git status --porcelain` 必须为空；
5. 更新 `ops/进度.md`。

## 7. 异常处理

| 情况 | 处理 |
|---|---|
| 文件缺失/过短 | 用 `sessionID` 追问同一子会话 |
| 越权写入 | 停批、修 `permissions`、重跑冒烟 |
| 数字冲突 | 先改 `_shared`，再重跑受影响篇 |
| push 失败 | 本地保留；按 E6 流程回退 HTTPS |
| `vps-*` 不可见 | `/reload`；仍不可见则用 `general` |

## 8. 坏文件隔离

- 坏的是最后一个提交：`git switch -c release/v1 HEAD~1`
- 坏的在中间：从坏提交之前的 sha 开 `release/v1`，cherry-pick 后续好提交
- 坏的是整批：从上一批标签开 `release/v1`
- 或 `git switch -c release/v1 draft/v1 && git revert --no-edit <sha>`

## 9. 推送（E6）

1. `git status --porcelain` 为空；
2. `git push -u origin draft/v1`；
3. `git push origin --tags`；
4. SSH 失败：`GIT_TERMINAL_PROMPT=0`，改用 `https://github.com/foreverturning/how-to-choice-vps.git`；
5. 无论成败，向用户报告 SSH 结果。
