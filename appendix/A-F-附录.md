## B. 成本计算过程

这一节回答“**50 / 15 / 3 元/月是怎么来的，能不能复算**”。全部口径以 [三档成本模型](../_shared/三档成本模型.md) 为唯一来源；本附录只做汇编，不另设参数。

### B.1 三档假设

| 维度 | A 合规大厂 | B 中小 IDC | C 灰色超售 / 跑路盘 |
|---|---|---|---|
| 硬件新旧 | 新机为主，3–5 年内在保 | 新机 + 二手混用，5–8 年 | 折旧期满、洋垃圾、翻新拼装 |
| 采购价系数 k | 1.0 | 0.2–0.4 | 0.05–0.15 |
| 机房 | 自建/合建，Tier III | 租用地方 IDC，单线或低线 | 民房/小机房，可能无 UPS、无消防 |
| 带宽 | BGP 多线，有最低保证带宽 | 共享 1:5–1:10，单线或假 BGP | 1:10–1:20 超售、NAT 汇聚、达量限速 |
| CPU 超售比 | 1:1–2:1 | 2:1–4:1 | 4:1–8:1 |
| IPv4 | 独立 IP | 独立为主，部分复用 | NAT / 共享为主 |
| 合规 | 备案 + IDC/ISP 证 + 可开票 | 有证或挂靠，部分可开票 | 无证、无备案、无发票 |
| 会计寿命 | 5 年 | 3 年（二手剩余寿命） | 0（已折完，只计残值） |

**基准配置**：2 vCPU / 2 GB / 40 GB SSD / 1 个 IPv4 / 峰值 3–5 Mbps。
**摊薄假设**：一台双路服务器（64 核 128 线程 / 512 GB）按 CPU 2:1 超分、内存不超分，切 **100–200 个** 2C2G，基准 150 个。这是全模型最敏感的假设：切 100 个还是 200 个，单 VM 成本差一倍，所以任何结论都必须带这个区间。

### B.2 换算口径

| 口径 | 取值 | 用在哪 |
|---|---|---|
| 1 月 | 730 小时 | 电力、IP 保有费、按小时计费 |
| 1 USD | ≈ 7.2 CNY | 海外报价折算，取整到元 |
| 1 Mbps | ≈ 0.125 MB/s | 带宽与下载速度互换 |
| 月流量 | 带宽 × 0.125 × 3600 × 24 × 30 ÷ 1024 × 利用率 | 判断固定带宽与按流量谁便宜 |
| 年成本 | 月成本 × 12 | 与售价对比算 R |

### B.3 五条公式

```text
① 硬件折旧/VM = P × k × (1 − r) / (N × V)
② 机柜电力/VM = (R_cab / H + W × 730 × e × PUE) / V
③ 带宽/VM     = B_保证 × u / V
④ IPv4/VM     = n × p_ip / V ÷ 复用系数
⑤ 运维/VM     = C_ops / V

汇总式：单 VM 月成本 = ① + ② + ③ + ④ + ⑤

P      整机购置价（新机口径，元）
k      硬件新旧系数：A 1.0 / B 0.2–0.4 / C 0.05–0.15
r      残值率 5%–10%
N      折旧月数：A 60 / B 36 / C 0（已折完，按残值摊）
V      摊薄 VM 数：100–200，基准 150
R_cab  整柜月租（元）      H 每柜机器数
W      单机功率（kW）       e 电价（元/kWh）      PUE 1.0–1.5
B_保证 整机保证带宽（Mbps）  u 带宽单价（元/Mbps/月）
n      独立 IP 数           p_ip IPv4 单价（元/月）
C_ops  运维 + 合规 + 获客月摊（元）
```

### B.4 基准值与自洽校验

| 成本项（元/VM/月，2026-11 口径） | A 合规大厂 | B 中小 IDC | C 灰色超售 |
|---|---:|---:|---:|
| 硬件折旧 | 12 | 3 | 0.2 |
| 机柜电力 | 8 | 3 | 1.0 |
| 带宽 | 13 | 6 | 1.2 |
| IPv4 | 3 | 2 | 0.3 |
| 运维/合规/获客 | 14 | 1 | 0.3 |
| **月成本** | **50** | **15** | **3.0** |
| **年成本（×12）** | **600** | **180** | **36** |

校验：12+8+13+3+14 = 50，×12 = 600；3+3+6+2+1 = 15，×12 = 180；0.2+1.0+1.2+0.3+0.3 = 3.0，×12 = 36。三档比值 17 : 5 : 1。

从整机倒推的三个关键参数（用于说明基准值不是拍脑袋）：整机购置价 A 12 万元 / B 1.8 万元 / C 1,500 元；折旧月数 60 / 36 / 按残值摊；摊薄 150 台。A 档 1,800 ÷ 150 = 12.0，B 档 450 ÷ 150 = 3.0，C 档 25 ÷ 150 ≈ 0.2。

> **一个必须讲清的口径**：A 档的“保证带宽”只有 16 Mbps ÷ 150 ≈ 0.1 Mbps/VM。这是“成本可覆盖”的口径，不是“5M 独享”。大厂轻量卖的是 3–5 Mbps 峰值、共享出口；合同一旦写“5M 独享”，成本立刻不成立。

### B.5 饼图口径与“区间型不精确加总”

饼图按**基准值 ÷ 合计**画，各列分项加起来等于一整块，只用于教学对比，不是会计数据。

| 成本项 | 图 1：A | 图 2：B | 图 3：C |
|---|---:|---:|---:|
| 硬件折旧 | 24.0% | 20.0% | 6.7% |
| 机柜电力 | 16.0% | 20.0% | 33.3% |
| 带宽 | 26.0% | 40.0% | 40.0% |
| IPv4 | 6.0% | 13.3% | 10.0% |
| 运维/合规/获客 | 28.0% | 6.7% | 10.0% |

三条读图规则：

1. **区间型不做精确加总**。区间带（如 A 档硬件 22–26%）用于说明误差范围，五项区间上限相加必然超过一整块，这不代表算错。
2. **成本饼与售价饼分开画**。C 档售价里另有一块“风险/其他”（跑路预备金、无证罚款风险、渠道抽成），约占售价 25–45%，不属于成本项，不得并入上面三张成本饼。
3. **百分比只解释结构，不解释到手价**。A 档“运维 28%”看着最贵，摊到每台也只有 14 元/月；C 档“带宽 40%”摊到每台只有 1.2 元。

### B.6 红灯阈值怎么用

判定式：`R = 实际年付价 ÷ 该档年成本地板`。R ≥ 1.5 绿灯；1.0–1.5 黄灯；0.5–1.0 红灯；< 0.5 黑灯；年红灯线 = 年地板 × 0.5（2C2G：A 300 / B 90 / C 18）。

| 配置 | A 年地板 | A 红灯线 | B 年地板 | B 红灯线 | C 年地板 | C 红灯线 |
|---|---:|---:|---:|---:|---:|---:|
| 1C1G | 330 | 165 | 100 | 50 | 20 | 10 |
| 2C2G | 600 | 300 | 180 | 90 | 36 | 18 |
| 2C4G | 750 | 375 | 225 | 113 | 45 | 23 |
| 4C8G | 1,200 | 600 | 360 | 180 | 72 | 36 |
| 8C16G | 2,160 | 1,080 | 648 | 324 | 130 | 65 |

三条使用注意：**先判档再算 R**（跨档比较会把所有低价机误判成黑灯）；**首年补贴是唯一合法的红灯例外**，判断要用续费价并标注“首年补贴”；**同一售价可落在不同档**（100 元/年 对 B 档 R≈0.56、对 C 档 R≈2.8），所以问题不是“便宜”，而是“宣称配置超出该档物理可能”。

### B.7 与总纲旧口径的差异

总纲 10.3 的示意饼图与成本模型存在 1–3 个百分点的差（A 列 25/17/25/6/27 对 24/16/26/6/28；B 列 15/25/35/8/17 对 20/20/40/13.3/6.7），原因是 10.3 为独立示意口径、未从 5.6 的基准值反推。**统一采用成本模型的 24/16/26/6/28**，10.3 保留“示意，非精确会计数据”的标注，不再回改其数字。

## C. 查验命令与工具清单

这一节回答“**拿到一台机器，怎么在半小时内判断它是不是它宣称的那台**”。命令按五组排列，可直接复制；仅在自己的机器或已获授权的机器上执行，`dmidecode`、`smartctl`、`ipmitool` 需 root，测速会消耗流量与 IO。

### C.1 硬件新旧（判断属于哪一档）

```bash
# 整机厂商/型号/序列号：核对是否与宣传一致
dmidecode -t system | grep -E "Manufacturer|Product Name|Serial Number"
# 主板与 BIOS 日期：老日期通常意味着老平台
dmidecode -t bios | grep -E "Version|Release Date"
# CPU 型号与代数：判断是当季还是十年前
lscpu | grep -E "Model name|Socket|Core|Thread|MHz"
# 内存条数量/单条容量/频率：品牌频率混杂多为拼装
dmidecode -t memory | grep -E "Size|Speed|Manufacturer|Part Number" | head -20
# 机械盘还是 SSD：ROTA=1 是机械盘
lsblk -d -o NAME,ROTA,MODEL,SIZE
# SATA/SAS 盘通电时长与重映射扇区：判断是否二手
smartctl -a /dev/sda | grep -E "Device Model|Serial|Power_On_Hours|Reallocated_Sector"
# NVMe 通电时长与寿命消耗：percentage_used 越高越接近报废
nvme smart-log /dev/nvme0 | grep -E "power_on_hours|percentage_used|media_errors"
# 带外管理资产标签：能看到 FRU 说明进的是正规机房
ipmitool fru 2>/dev/null | head -30
```

读法：`Power_On_Hours` > 3 万小时（约 3.4 年连续运行）→ 二手；`percentage_used` > 20% → 盘接近寿命尾声；内存品牌/频率不一致 → 拼装。

### C.2 性能与超售

```bash
# CPU steal：st 长期偏高是超售最直接的证据
top -bn1 | head -8
# 分核负载：看是否只有一个核在跑、其余被邻居占满
mpstat -P ALL 1 5
# 上下文切换与等待队列：r 列长期大于核数说明排队
vmstat 1 5
# PSI 压力指标：some avg10 持续 >10 说明被邻居拖累
cat /proc/pressure/cpu 2>/dev/null
# 2 核理论算力基线：与同型号独服对比才有意义
sysbench cpu --threads=2 run
# 4K 随机读写：共享存储会明显偏低且抖动大
fio --name=randrw --ioengine=libaio --rw=randrw --bs=4k --size=1G --numjobs=4 --runtime=60 --time_based --group_reporting
# 顺序读：远低于 100 MB/s 说明走的是网络存储
fio --name=seqread --rw=read --bs=1M --size=1G --numjobs=1 --runtime=30 --time_based --group_reporting
```

> ⚠️ 会写 1 GB 文件，生产环境避开业务高峰。

```bash
# 最粗暴的落盘测试：看真实写入速度，跑完自动删除
dd if=/dev/zero of=./test.bin bs=1M count=1024 oflag=direct && rm -f ./test.bin
```

读法：`st` 长期 >5%、晚高峰 >20% → 超售；4K 随机写 <500 IOPS → 机械盘或严重限速；同一台机器晚高峰与凌晨差 30% 以上 → 邻居在抢资源。

### C.3 网络与线路

```bash
# 单线程下行：输出为 B/s，×8÷1e6 得 Mbps
curl -s -o /dev/null -w "down=%{speed_download} B/s\n" "https://speed.cloudflare.com/__down?bytes=100000000"
# 多线程压测：需自建 iperf3 服务端，才能测出真实上行/下行
iperf3 -c <server> -t 60 -P 8
# 丢包与跳数：晚高峰跑一次、凌晨再跑一次对比
mtr -rw -c 50 <target>
# 回程路由：看是否真 CN2（全程 59.43.x.x / AS4809）
traceroute -T -p 443 <target>
# 连续采样：观察是否规律性劣化
for i in $(seq 1 10); do ping -c 20 1.1.1.1 | tail -1; sleep 60; done
```

读法：晚高峰速率 < 标称 50% → 共享带宽；回程出现 202.97 而非 59.43 → 不是 CN2 GIA；三网 `mtr` 中某一网绕路 200ms+ → 假 BGP。

### C.4 IP 类型与信誉

```bash
# 出口 IP：与面板显示对比，不一致就要怀疑
curl -s https://ifconfig.me; echo
# IP 归属与 ASN：看是国家/地区、机房还是住宅宽带
curl -s https://ipinfo.io/json
# 本机网卡地址：出现 10.x / 172.16.x / 100.64.x 而出口是公网 → NAT
ip -4 addr show
# 默认路由：确认流量从哪块网卡出去
ip route get 1.1.1.1
# 监听端口：NAT 机常见只映射少数端口
ss -tlnp
# whois 归属：netname 与宣传地区不符 → 转卖或套牌
whois <ip> | grep -Ei "netname|country|org|descr"
# 滥用信誉：abuseConfidenceScore > 25 视为脏 IP
curl -s "https://api.abuseipdb.com/api/v2/check?ipAddress=<ip>&maxAgeInDays=90" -H "Key: <your_key>" -H "Accept: application/json"
```

读法：`ip addr` 是内网段而出口是公网 → NAT；IP 归属为住宅宽带或不明组织 → 不是机房 IP；外部 `nc -vz <ip> 443` 不通 → 有额外防火墙或端口未映射。

## D. 工信部 IDC/ISP 许可证查询步骤

这一节回答“**怎么在五分钟内确认这家公司有没有资格卖机房和带宽**”。结论：查得到证只说明“主体合规”，不等于“你这台机器达标”；查不到证，则可以直接放弃年付。

### D.1 八步查询

1. **拿到公司全称**。从商家官网底部、关于页、发票抬头或合同里找**工商注册全称**（不是品牌名、不是店铺名、不是英文名）。拿不到全称，本身就是一条风险信号。
2. **打开工信部电信业务市场综合管理信息系统**：浏览器访问 `https://dxzhgl.miit.gov.cn`。这是许可证的官方公示入口，不是备案入口。
3. **选“许可信息查询”**（部分版本写作“许可证查询”“电信业务经营许可查询”）。不要点“备案查询”，那是另一套系统。
4. **选查询方式**：优先“企业名称”，输入第 1 步拿到的全称；已知许可证编号时也可按编号反查主体。
5. **填验证码并提交**。名称含括号、空格时按营业执照原样输入，否则会查无记录。
6. **看结果列表**，逐项核对六个字段（见 D.2 表）。同一家公司可能有多张证，要挑与你购买行为对应的那张。
7. **判断业务种类与覆盖范围**。卖云主机/机柜托管，看是否含“互联网数据中心业务”；卖接入/带宽，看是否含“互联网接入服务业务”。再看覆盖范围是否包含你机器所在省市——跨省经营需相应覆盖。
8. **交叉验证三件事**：① 域名备案主体（`beian.miit.gov.cn`）是否与许可证主体一致；② 发票抬头是否与许可证主体一致；③ 合同签约方是否与许可证主体一致。三者有一个对不上，就是挂靠或转租。

### D.2 六个必看字段

| 字段 | 看什么 | 异常信号 |
|---|---|---|
| 企业名称 | 与营业执照、发票、合同是否完全一致 | 名称近似但不一致（多字、少字、换字） |
| 许可证编号 | 是否存在、格式是否完整 | 只给“备案号”冒充许可证号 |
| 业务种类 | 是否含 IDC / ISP 对应业务 | 只有 CDN、呼叫中心等无关种类 |
| 覆盖范围 | 是否含机器所在省市 | 范围是 A 省，机器在 B 省 |
| 有效期 | 起止日期，是否已过期 | 已过期仍在使用，或临近到期 |
| 发证机关 | 是否为通信管理局/工信部 | 冒用其他行业许可证 |

### D.3 结果判读

| 查询结果 | 结论 | 动作 |
|---|---|---|
| 有证、种类对、范围含当地、在有效期内、主体三处一致 | 主体合规 | 可进入价格与验机环节，仍需看 SLA 与合同 |
| 有证但主体与卖家不一致 | 挂靠 / 转租 | 要求出示授权链，否则按无证处理 |
| 有证但业务种类不含 IDC/ISP | 超范围经营 | 不年付，不存放业务数据 |
| 有证但覆盖范围不含当地 | 跨区经营 | 追问实际机房位置，要求写入合同 |
| 许可证已过期 | 视同无证 | 直接放弃 |
| 查无记录 | 无证经营 | 只当一次性玩具，绝不年付 |

### D.4 三个常见误区

- **“有 ICP 备案 = 有 IDC 证”**：错。备案是网站域名的行政登记，IDC/ISP 是电信业务经营许可，两套系统、两个入口。
- **“证在办 = 马上就有”**：错。办证周期以月计，期间销售属于无证经营；合同里写“证在办”不构成免责。
- **“大厂代理 = 大厂资质”**：错。代理卖的是转售资源，出问题时资质主体不一定是收款方；要看**收款方**的证。
