# 元规则：本册规则如何被质疑与修订

> 定位：治理层（约定层）。本文件不产生事实结论，只规定「规则本身怎么被改」。
> 优先级：`_shared/00-元规则.md` > `_shared/写作规范.md` > 单篇习惯；事实层仍以 `ops/数据变更记录.md` 的 `data-version` 与 `_shared/价格快照-2026-11.md` 的 `S-` 编号为准。
> 适用：全库所有规则条款，含本文件自身。

## 0. 一句话

本册所有规则都是**带版本、可被质疑、可被修订的约定，不是事实**。信息不全面本身就是一条合法的质疑理由；任何条款（含本章）都不能自称「不可质疑」来阻断流程。

**为什么要有这一层**：2026-11-14 复盘发现，结论句被写成禁写规则后，后续取证只在既有范围内补证据、没有做过反例检索，导致「国内独立第三方 BaaS / 跨端 Serverless 聚合商」整类在九组来源前缀里没有位置（见 `RQ-01`）。规则的原意是让结论可复核，副作用是把检索范围也钉死了。（本句为复盘记录，按 `【开发者自述】` 处理。）

## 1. 规则分三层

| 层 | 包含什么 | 怎么改 |
|---|---|---|
| L0 最小内核 | 只锁一条结构要求：必须同时存在「质疑入口 + 修订流程 + 反封闭检查」 | 三件套不可删除；其**具体实现**可整章替换 |
| L1 结构约定 | 编号空间隔离、五档证据分层、唯一事实源、文件分工、附表登记 | 开 `CR-`，列影响面，逐篇同步后回填回执 |
| L2 操作细则 | 禁用词表、表格列数、口径句、筛选器、锚点写法、自查清单 | 直接改 + 补一行 `CR-` 记录，不升 `data-version` |

**怎么读**：分层不是为了把规则供起来，是为了让「改规则」的成本和改动范围相称。L0 锁的是「必须有个机制」，不锁任何一句具体文字——把本章整章换掉也合规，只要新文本回答了「谁可以质疑 / 怎么改 / 怎么防封闭」三问。

> **约定层与事实层的关系**：本文件及 §1 各层条款是规范性指令，不适用 `_shared/写作规范.md` 第二节的五档事实分层；五档只约束事实断言。约定层里引用事实（如「某文件第几行写了什么」）时，按该事实原出处所标等级回指。此豁免本身是 `CR-001` 的一部分，可被 `RQ-` 质疑。

## 2. 默认可改声明

- 全库规则条款一律适用本章：`_shared/写作规范.md` 全篇、README 的「三条硬规矩」、`00-总纲.md` 的「三条军规」、`ops/` 的变更与同步流程、`emmm/` 的四种期限形态筛选器、各篇的口径句与自查清单。
- 任何条款**不得**以「本规范规定」「历史约定」「一直如此」为由拒绝登记质疑；最多标为 L0 并写明理由，理由本身可被 `RQ-` 质疑。
- 规则与可复核的事实冲突时，以事实为准并开 `CR-` 修订规则，**不允许**用规则去否定事实。这一条直接约束 `emmm/` 这类筛选器：筛选器只决定「本次取样收不收」，不决定「这类方案存不存在」。

## 3. 质疑入口 `RQ-NN`

登记表固定 6 列。开一条质疑的门槛只有「写清楚指向哪条规则」。

| 列 | 填什么 |
|---|---|
| 编号 | `RQ-` 两位数字，连续，唯一落点本文件 |
| 指向 | 哪条规则：文件相对路径 + 小节 |
| 疑似问题 | 漏了什么 / 哪里错 / 哪里把范围钉死了 |
| 线索 | 任意线索；可二手、可直觉、可不完整 |
| 状态 | `待处置` / `已转 CR-` / `暂缓（写明理由）` |
| 登记日期 | 日期 |

**门槛说明**：开 `RQ-` 不要求举证、不要求给替代方案、不要求先证明规则有错。「我们掌握的信息不全面」「这一类供应商是不是根本没查」都是有效质疑。质疑登记即生效为待处置项，不因「证据不足」被退回；是否修、何时修，另由 `CR-` 决定。

## 4. 修订流程 `CR-NN`

登记表固定 6 列。

| 列 | 填什么 |
|---|---|
| 编号 | `CR-` 两位数字，连续，唯一落点本文件 |
| 来源 | 由哪条 `RQ-` 或哪次复核触发 |
| 层与条款 | L0 / L1 / L2 + 具体条款 |
| 变更前→后 | 旧措辞 → 新措辞，或新增 / 撤销 |
| 影响面 | 受影响文件清单，逐篇同步 |
| 版本与回执 | 是否升 `data-version` + 维护者 / 日期 / `git diff` 校验 |

**流程**：`RQ-` 或季度复核 → 开 `CR-` → 列影响面 → 逐篇定点改 → 回填「已同步」+ 回执 → 收尾。复用 `ops/数据变更记录.md` 第三节的同步步骤，不另造第二套台账。

**升版规则**（沿用 `ops/数据变更记录.md` 第二、三节）：纯规则修订不升 `data-version`、不占 `DC-`；只有当修订改到 `S-` 数值、增删 `S-` 条目或实质修改 `TERM-` 定义时，才登记新 `DC-` 行并 +1。规则改动与数据改动因此可以独立演进，互不阻塞。

## 5. 反封闭三检查（每轮取证与每次写结论前强制执行）

| 检查 | 做什么 | 不做的后果 |
|---|---|---|
| C1 供给侧穷举 | 凡写「唯一 / 不存在 / 只有 / 全都不 / 含『最』的比较级」这类封闭性结论，先列**候选集类别清单**并写明穷举范围；未穷举则降级为「本册已核实范围内…」并登记 `UNK-` | 结论先行，后续只在补证据 |
| C2 反例检索 | 每轮至少做一次**专门找反例**的检索（检索式含否定或替代词），结果无论有无都留一行 | 把「没查到反例」当成「已穷举」 |
| C3 约定≠事实 | 所有筛选器、口径、取舍规则标 `【约定·可质疑】`；禁止用它推出「某类对象不存在」；事实结论只由 `S-` 编号与来源 URL 支撑 | 取样口径伪装成事实源 |

**怎么读**：这三条不是给结论加更多约束，是给**覆盖面**留门。C1 管「说满了没有」，C2 管「往范围外看过没有」，C3 管「是不是把约定当成了事实」。

## 6. 覆盖面扩展协议

`RQ-` 若指向「整类供给侧 / 整类方案缺失」，处置方式是**按类别横扫**：先列类别清单，再逐家统一取四个字段（0 元档是否存在、是否需自备已备案域名、额度与期限形态、超限是停服还是扣费），逐条登记一手来源；**不按名字补一条**了事。横扫后必须回头更新 C1 的候选集清单，并把「供给侧未穷举」登记为 `UNK-`，即使本轮已扫过若干层也保留该登记。

## 7. 日落与复核

- 每条 L2 条款默认带「上次复核日期」；季度重扫时未复核的自动降为 `待复核` 态，继续沿用须显式写明已复核。
- 规则会过期：`【约定·可质疑】` 不是免责声明，是提醒下一位维护者「这条可以再想一遍」。
- 复核不只查「有没有违反规则」，还要查「规则本身是不是漏了什么」；后者写入 `ops/数据变更记录.md` 第四节季度复核清单。

## 9. 本章怎么被改

用 `CR-` 改本章，与改其它条款同一流程。若整章替换，新文本须回答三问：谁可以质疑、怎么改、怎么防封闭；三问缺失即视为 L0 未满足，不因其自称「元规则」而自动生效。
