## 一、口径与三条铁律

| 铁律 | 含义 |
|---|---|
| **不含利润** | 表里的"成本"是厂商侧成本地板，不含毛利、税、支付通道费、坏账 |
| **只给量级** | 所有数字是量级估算，不追求会计精度；正文写区间，附录写推导 |
| **可复算** | 任何一档的合计必须等于分项之和，年成本必须等于月成本 × 12 |

**数字来源标签**（全文统一使用）：

- `【快照】`：来自 `_shared/价格快照-2026-11.md`（S2），带编号与核对日期
- `【建模】`：本文件的假设与推导，非任何厂商披露
- `【公开】`：财报、RIR 报价、行业公开数据
- `【待核】`：暂用总纲口径，等 S2 落地后回填

**基准配置**：2 vCPU / 2 GB 内存 / 40 GB SSD / 1 个 IPv4 / 峰值 3–5 Mbps。
**换算**：1 月 = 730 小时；1 USD ≈ 7.2 CNY；1 Mbps ≈ 0.125 MB/s。

## 二、三档定义与假设

| 维度 | A 合规大厂 | B 中小 IDC | C 灰色超售 / 跑路盘 |
|---|---|---|---|
| **硬件新旧** | 新机为主，3–5 年内在保 | 新机 + 二手混用，5–8 年 | 折旧期满、洋垃圾、翻新拼装，8 年以上 |
| **采购价系数 k** | 1.0（新机价） | 0.2–0.4 | 0.05–0.15 |
| **机房** | 自建/合建，Tier III 级 | 租用地方 IDC，单线或低线机房 | 民房、小机房，可能无 UPS / 消防 |
| **带宽类型** | BGP 多线，有**最低保证带宽** | 共享带宽 1:5–1:10，单线或假 BGP | 1:10–1:20 超售、NAT 汇聚、达量限速 |
| **CPU 超售** | 1:1–2:1 | 2:1–4:1 | 4:1–8:1 |
| **IPv4** | 独立 IP，批发 + 零售 | 独立为主，部分复用 | NAT / 共享 IP 为主 |
| **合规状态** | ICP 备案 + IDC/ISP 证 + 等保，可开票 | 有证或挂靠，部分可开票 | 无证、无备案、无发票 |
| **运维** | 7×24 + SLA | 工单制，工作时间 | 无，靠群聊 |
| **获客** | 广告、代理返佣，成本高 | 社区口碑 | 低价引流、收预付款 |
| **摊薄 VM 数** | 100–200（基准 150） | 100–200（基准 150） | 100–200（基准 150，实际常更密） |
| **会计寿命** | 5 年 | 3 年（二手剩余寿命） | 0（已折完，只算残值） |
| **主要风险** | 溢价、续费涨价、生态绑定 | 超售、线路差、售后慢 | 跑路、关停、数据丢失、IP 被墙 |

**摊薄假设说明**：一台双路服务器（64 核 128 线程 / 512 GB）按 CPU 2:1 超分、内存不超分，可切 150 个 2C2G。**同一台机器切 100 个还是 200 个，单 VM 成本差一倍**——这是本模型最敏感的假设，引用时必须带"100–200"这个区间。

## 三、单 VM 月成本表（核心表）

单位：元 / VM / 月。"基准"列用于计算，分项相加**严格等于**合计。

| 成本项 | A 区间【建模】 | **A 基准** | B 区间【建模】 | **B 基准** | C 区间【建模】 | **C 基准** |
|---|---:|---:|---:|---:|---:|---:|
| 硬件折旧 | 8–15 | **12** | 3–7 | **3** | 0–1 | **0.2** |
| 机柜电力 | 5–10 | **8** | 3–6 | **3** | 1–3 | **1.0** |
| 带宽 | 8–15 | **13** | 3–8 | **6** | 1–4 | **1.2** |
| IPv4 | 2–3 | **3** | 1–2 | **2** | 0–1 | **0.3** |
| 运维/合规/获客 | 7–17 | **14** | 1–2 | **1** | 0–1 | **0.3** |
| **合计（月成本）** | 30–60 | **50** | 10–25 | **15** | 2–10 | **3.0** |
| **年成本（月 × 12）** | 360–720 | **600** | 120–300 | **180** | 24–120 | **36** |
| **常见售价（元/年）** | 首年 99–300；续费 300–800 | — | 100–300 | — | 30–100，或所谓"永久" | — |
| **判断** | 首年补贴，续费接近成本 | — | 可持续的便宜，有妥协 | — | 必然有猫腻或高风险 | — |

**自洽校验（发布前必查）**

- A：12 + 8 + 13 + 3 + 14 = **50** ；50 × 12 = **600** ✅
- B：3 + 3 + 6 + 2 + 1 = **15** ；15 × 12 = **180** ✅
- C：0.2 + 1.0 + 1.2 + 0.3 + 0.3 = **3.0** ；3.0 × 12 = **36** ✅
- 三档比值 A : B : C ≈ **17 : 5 : 1**，落在军规 4 的"压到 1/5–1/50"区间内 ✅

> ⚠️ **区间端点不可相加**：5.6 的区间是各项独立波动的范围，不是同一条成本线上同时取到。A 档"全部取最低"= 30、"全部取最高"= 60 都只是边界，不代表任何一台真实机器。计算器只输出基准值 ± 扰动。
>
> ⚠️ **售价行标签不同**：成本五行是【建模】，"常见售价"行是【待核】（来源总纲 5.6，等 S2 快照校准）。不要把它当快照价引用。

## 四、从整机推导到单 VM（可复算）

| 参数 | A 合规大厂 | B 中小 IDC | C 灰色超售 |
|---|---:|---:|---:|
| 整机购置价 P | 12 万元 | 1.8 万元 | 1,500 元 |
| 折旧月数 N | 60 | 36 | 60（已折完，仅计残值） |
| 残值率 r | 10% | 10% | 0 |
| 月折旧 = P×(1−r)/N | 1,800 | 450 | 25 |
| 摊薄 VM 数 V | 150 | 150 | 150 |
| **硬件/VM** | 1,800/150 = **12.0** | 450/150 = **3.0** | 25/150 = **0.17 → 0.2** |
| 机柜月租（整柜） | 6,000 | 2,250 | 0（民房） |
| 每柜机器数 H | 8 | 10 | — |
| 单机功率 W | 0.55 kW | 0.40 kW | 0.35 kW |
| PUE | 1.5 | 1.3 | 1.0 |
| 电价 e | 0.75 元/kWh | 0.60 元/kWh | 0.60 元/kWh |
| 电力/月 = R/H + W×730×e×PUE | 750+452 = 1,202 | 225+228 = 453 | 0+153 = 153 |
| **电力/VM** | 1,202/150 = **8.0** | 453/150 = **3.0** | 153/150 = **1.0** |
| 整机保证带宽 | 16 Mbps | 20 Mbps | 7.5 Mbps |
| 带宽单价 u | 120 元/Mbps | 45 元/Mbps | 24 元/Mbps |
| **带宽/VM** | 16×120/150 = 12.8 → **13** | 20×45/150 = **6.0** | 7.5×24/150 = **1.2** |
| **IPv4/VM** | 150×2.5，加 20% 备用 → **3.0** | 150×2.0 → **2.0** | NAT 共享 → **0.3** |
| 运维/合规/获客月摊 | 2,100 | 150 | 45 |
| **运维/VM** | 2,100/150 = **14.0** | 150/150 = **1.0** | 45/150 = **0.3** |
| **推导合计** | **50.0** | **15.0** | **3.0** |

**两个必须讲清的口径**

1. **A 档的"保证带宽"只有 0.1 Mbps/VM**（16 Mbps ÷ 150）。这是"成本可覆盖"的口径，不是"5M 独享"。大厂轻量卖的是 3–5 Mbps **峰值**、共享出口，保证值很低；一旦合同写"5M 独享"，成本立刻不成立（见下）。
2. **IPv4 批发价 2.2–2.5 元/月**（$0.30–0.35 × 7.2）【公开】。C 档 0.3 元只可能来自 NAT 或复用。

**"5M 独享"反算（打脸利器）**：150 台 VM × 5 Mbps = 750 Mbps；即便按最便宜的灰色带宽 24 元/Mbps 计，也要 18,000 元/月 = **120 元/VM/月 = 1,440 元/年**。卖 60 元/年，只有地板的 **1/24**。所以"2C2G + 独立 IP + 5M 独享 + 60 元/年"在物理上不成立，必然是共享 / NAT / 限速 / 跑路中的至少一项。

## 六、成本地板公式

```text
单VM月成本 = 硬件折旧 + 机柜电力 + 带宽 + IPv4 + 运维合规获客

硬件折旧/VM = P × k × (1 − r) / (N × V)
机柜电力/VM = (R_cab / H + W × 730 × e × PUE) / V
带宽/VM     = B_保证 × u / V
IPv4/VM     = n × p_ip / V ÷ 复用系数
运维/VM     = C_ops / V

P     整机购置价（元，新机口径）
k     硬件新旧系数：A 1.0 / B 0.2–0.4 / C 0.05–0.15
r     残值率 5%–10%
N     折旧月数：A 60 / B 36 / C 0（已折完按残值摊）
V     摊薄 VM 数：100–200，基准 150
R_cab 整柜月租（元）    H 每柜机器数    W 单机功率 kW
e     电价（元/kWh）    PUE 制冷配电系数 1.0–1.5
B_保证 整机保证带宽（Mbps）  u 带宽单价（元/Mbps/月）
n     独立 IP 数        p_ip IPv4 单价（元/月）
C_ops 运维+合规+获客月摊（元）
```

**其他配置怎么换算**

| 配置 | 系数 | A 月地板 | B 月地板 | C 月地板 |
|---|---:|---:|---:|---:|
| 1C1G | 0.55 | 27.5 | 8.3 | 1.7 |
| 2C2G（基准） | 1.00 | 50.0 | 15.0 | 3.0 |
| 2C4G | 1.25 | 62.5 | 18.8 | 3.8 |
| 4C8G | 2.00 | 100.0 | 30.0 | 6.0 |
| 8C16G | 3.60 | 180.0 | 54.0 | 10.8 |

> 系数只反映 CPU/内存的边际成本；**带宽和 IP 不随配置线性增长**，若配置里带宽翻倍，需在结果上单独加带宽增量。地区系数：一线城市 ×1.2–1.4，西部/内蒙 ×0.7–0.9，海外另建模型（见 5.9）。**年地板 = 月地板 × 12 后取整到 5 元**（第七节据此填表）。

## 七、红灯阈值（配置 × 档位）

**判定规则**（来自 5.7，本文件只做落地换算）：

```text
比值 R = 实际年付价 ÷ 该档年成本地板
R ≥ 1.5        🟢 绿灯：价格覆盖成本且有合理毛利
1.0 ≤ R < 1.5  🟡 黄灯：贴着地板，可能超售，必须验机
0.5 ≤ R < 1.0  🔴 红灯：低于地板，必然有猫腻
R < 0.5        ⚫ 黑灯：跑路盘高危
```

**年红灯线 = 年地板 × 0.5**（低于此线直接红/黑）：

| 配置 | A 年地板 | A 红灯线 | B 年地板 | B 红灯线 | C 年地板 | C 红灯线 |
|---|---:|---:|---:|---:|---:|---:|
| 1C1G | 330 | 165 | 100 | 50 | 20 | 10 |
| 2C2G | 600 | 300 | 180 | 90 | 36 | 18 |
| 2C4G | 750 | 375 | 225 | 113 | 45 | 23 |
| 4C8G | 1,200 | 600 | 360 | 180 | 72 | 36 |
| 8C16G | 2,160 | 1,080 | 648 | 324 | 130 | 65 |

**使用注意**

- **首年补贴是唯一合法的"红灯例外"**：大厂首年 99 元/年 的 2C2G，R = 99/600 = 0.17，按表是黑灯，但它有合规主体和续费价兜底。判断时必须用**续费价**，并标注"首年补贴"。
- **跨档比较没意义**：把 100 元/年 拿去和 A 档地板比，会得出"所有低价机都是黑灯"的错误结论。正确做法是先判断它属于哪一档，再在本档内比。
- **同一售价可落在不同档**：100 元/年 对 B 档 R=0.56（红灯，靠超售兑现），对 C 档 R=2.8（绿灯，但风险另计）。所以"便宜"本身不是问题，"便宜且声称的配置超出该档物理可能"才是问题。

## 八、价格体检评分卡（六维 / 权重 / 三色灯）

**计分**：每维 0–5 分，加权总分 = Σ(得分 ÷ 5 × 权重)，满分 100。

| 维度 | 权重 | 检查点 | 5 分 | 3 分 | 1 分 | 数据来源 |
|---|---:|---|---|---|---|---|
| 价格 vs 成本地板 | 30 | 续费价 ÷ 本档地板 | R ≥ 1.5 | 1.0–1.5 | 0.5–1.0 | 本文件第三/七节 |
| 资源真实性 | 20 | CPU 是否独享、内存是否 balloon、磁盘是否真 SSD、硬盘通电时长 | 型号对得上、通电 <2 万小时 | 有一项存疑 | 多项对不上 / 洋垃圾 | `dmidecode` `smartctl` `lscpu` |
| 网络质量 | 15 | 保证带宽、线路、晚高峰丢包、回程 | 晚高峰 ≥80% 标称、丢包 <1% | 60–80%、丢包 1–3% | <50%、丢包 >5%、绕路 | `iperf3` `mtr` `traceroute` |
| 稳定性/SLA | 15 | 成立年限、口碑、故障率、是否有备份 | ≥3 年、有 SLA、有快照 | 1–3 年、无正式 SLA | <1 年、查不到主体 | 工商/社区/工单记录 |
| 售后/合规 | 10 | 工单响应、退款条款、IDC/ISP 证、发票 | 有证、可开票、支持退款 | 挂靠、部分可开 | 无证、无票、不退款 | 工信部查询、合同 |
| 隐性限制 | 10 | 流量限速、超量计费、续费价、绑定条款 | 条款写明、无隐藏项 | 有 1–2 项限制 | 达量限速/自动转按量/续费翻倍 | 购买页、合同、客服 |

**灯号映射**

| 总分 | 灯 | 处理 |
|---|---|---|
| ≥ 80 | 🟢 绿 | 可买，按月付先试 |
| 60–79 | 🟡 黄 | 先月付验机，跑完 Lab 6 再年付 |
| 40–59 | 🔴 红 | 只用于学习/临时，不放业务与数据 |
| < 40 | ⚫ 黑 | 不买 |

**双轨取严**：最终灯 = min(总分灯, 价格灯)。**一票否决**（直接判黑）：查不到经营主体 + 只收年付 + 无发票 + 拒绝任何退款。

**示例**：某 2C2G、60 元/年、宣称独立 IP + 5M 独享。价格维 R = 60/36 = 1.67 → 5 分；但"5M 独享"反算需 1,440 元/年，资源真实性 1 分、隐性限制 1 分、合规 1 分。总分 = 30 + 4 + 9 + 9 + 2 + 2 = 56 → 🔴 红，且触发"宣称配置超出物理可能"降级为 ⚫。

## 九、查验命令清单（可直接复制）

> 仅在自己的机器或已获授权的机器上执行；`dmidecode`、`smartctl`、`ipmitool` 需 root。测速会消耗流量与 IO，生产环境避开高峰。

### 9.1 硬件新旧（判断属于哪一档）

```bash
# 整机厂商/型号/序列号
dmidecode -t system | grep -E "Manufacturer|Product Name|Serial Number"
# 主板与 BIOS 日期（老日期 = 老平台）
dmidecode -t baseboard | grep -E "Manufacturer|Product Name"
dmidecode -t bios | grep -E "Version|Release Date"
# CPU 型号与代数
lscpu | grep -E "Model name|Socket|Core|Thread|MHz"
cat /proc/cpuinfo | grep "model name" | uniq -c
# 内存条数量/单条容量/频率（判断是否拼装）
dmidecode -t memory | grep -E "Size|Speed|Manufacturer|Part Number" | head -20
# 机械盘还是 SSD
lsblk -d -o NAME,ROTA,MODEL,SIZE
# SATA/SAS 盘通电时长与重映射扇区
smartctl -a /dev/sda | grep -E "Device Model|Serial|Power_On_Hours|Reallocated_Sector"
# NVMe 通电时长与寿命消耗
nvme smart-log /dev/nvme0 | grep -E "power_on_hours|percentage_used|media_errors"
# 带外管理（能看到资产标签 = 正规机房）
ipmitool fru 2>/dev/null | head -30
```

**读法**：`Power_On_Hours` > 3 万小时（约 3.4 年连续运行）→ 二手；`percentage_used` > 20% → 盘接近寿命尾声；内存条品牌/频率不一致 → 拼装。

### 9.2 性能与超售

```bash
# CPU steal（st）——超售最直接的证据
top -bn1 | head -8
mpstat -P ALL 1 5
vmstat 1 5
# PSI（内核 4.20+）：some avg10 持续 >10 说明被邻居拖累
cat /proc/pressure/cpu 2>/dev/null
cat /proc/pressure/io 2>/dev/null
# 2 核理论算力基线（对比同型号独服）
sysbench cpu --threads=2 run
# 4K 随机读写 IOPS（共享存储会明显偏低且抖动大）
fio --name=randrw --ioengine=libaio --rw=randrw --bs=4k --size=1G \
    --numjobs=4 --runtime=60 --time_based --group_reporting
# 顺序读（看是否被限速）
fio --name=seqread --rw=read --bs=1M --size=1G --numjobs=1 \
    --runtime=30 --time_based --group_reporting
# 最粗暴的落盘测试（注意会写 1GB）
dd if=/dev/zero of=./test.bin bs=1M count=1024 oflag=direct && rm -f ./test.bin
```

**读法**：`st` 长期 >5% 或晚高峰 >20% → 超售；4K 随机写 <500 IOPS → 机械盘或严重限速；顺序读远低于 100 MB/s → 网络存储。

### 9.3 网络与线路

```bash
# 单线程下行：输出为 B/s，×8÷1e6 得 Mbps，÷1e6 得 MB/s
curl -s -o /dev/null -w "down=%{speed_download} B/s\n" \
  "https://speed.cloudflare.com/__down?bytes=100000000"
# 多线程压测（需自建 iperf3 服务端）
iperf3 -c <server> -t 60 -P 8
# 丢包与跳数（晚高峰跑一次，凌晨再跑一次对比）
mtr -rw -c 50 <target>
ping -c 50 <target> | tail -3
# 回程路由：看是否真 CN2（59.43.x.x / AS4809）
traceroute -T -p 443 <target>
# BGP 归属（浏览器打开，查 AS 与前缀）
# https://bgp.he.net/
```

**读法**：晚高峰速率 < 标称 50% → 共享带宽；去回程出现 202.97 而非 59.43 → 不是 CN2 GIA；三网 `mtr` 某一网绕路 200ms+ → 假 BGP。

### 9.4 IP 类型与信誉

```bash
# 出口 IP
curl -s https://ifconfig.me; echo
curl -s https://ipinfo.io/json
# 本机网卡上的地址（对比出口 IP，判断是否 NAT）
ip -4 addr show
ip route get 1.1.1.1
# 监听端口（NAT 机常见只映射少数端口）
ss -tlnp
# IP 归属与是否被标记
whois <ip> | grep -Ei "netname|country|org|descr"
# 信誉查询（需免费注册取 key）
curl -s "https://api.abuseipdb.com/api/v2/check?ipAddress=<ip>&maxAgeInDays=90" \
  -H "Key: <your_key>" -H "Accept: application/json"
```

**读法**：`ip addr` 里是 10.x/172.16.x/100.64.x 而出口是公网 → NAT；`abuseConfidenceScore` > 25 → 脏 IP；`country` 与宣传地区不符 → 转卖/套牌。

## 十、写作口径：哪些数字能直接用，哪些必须标"估算"

| 数字 | 来源 | 标签 | 使用限制 |
|---|---|---|---|
| 首年价 / 续费价 / 零售带宽价 / EIP 零售价 | S2 价格快照（待落地） | `【快照】`/`【待核】` | 必须带快照日期；正文只写区间，附录写编号 |
| 常见售价 99–300 / 100–300 / 30–100 | 总纲 5.6 | `【待核】` | S2 完成后逐条校准，可能微调 |
| 折旧年限 3–6 年、各厂商年限 | 总纲 10.1、财报 | `【公开】` | 引用时注明"会计年限≠物理寿命" |
| IPv4 批发 $0.30–0.35/IP/月 | 公开报价 | `【公开】` | 换算按 7.2，写"约 2.2–2.5 元" |
| 单 VM 五项成本、合计、年成本 | 本文件第三/四节 | `【建模】` | 必须同时给出"100–200 台摊薄"前提 |
| 整机价、机柜租金、电价、PUE、功率 | 本文件第四节假设 | `【建模】` | 不写成"某厂商实际成本" |
| 超售倍数 1:5–1:20、CPU 2:1–8:1 | 总纲 5.5 + 本文件 | `【建模】` | 用"常见于/量级"措辞，不给单一厂商定性 |
| 饼图百分比 | 本文件第五节 | `【建模】` | 必须带"区间型，不要求精确加总" |
| 评分卡权重与阈值 | 总纲 5.7 | `【建模】` | 权重不得在章节里改动 |

**三条写作纪律**

1. 正文出现成本数字时，**先说是哪一档**，再说数字；不写"云服务器成本大约 50 元"这种无档位表述。
2. 不写小数两位的"精确成本"（如 48.37 元），一律取整或取 0.5 的倍数，并加"量级估算"。
3. 任何"低于地板"的结论，必须给出**替代解释**（补贴 / 超售 / NAT / 限速 / 跑路）中的至少一项，不能只下判断。
