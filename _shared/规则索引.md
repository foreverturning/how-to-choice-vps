## 1. 加载协议（给 AI / 维护者）

1. 先读本索引这一份清单。
2. 按本次任务命中「什么时候读我」1~N 行。
3. **只读命中行的「全文路径 + 小节」，不读未命中的规范全文**。
4. 写结论前无条件做反封闭三检查、交稿前无条件过自查七条。
5. 未命中任何组时按 `_shared/00-元规则.md §6` 开 `RQ-` 补一行，不自行通读全库。
6. 季度复核按 `_shared/00-元规则.md §7` 查本索引有没有漏组。

### 1.1 扫描范围约定

> 状态：`【约定·可质疑】`。本条收敛的是「对规则文件的全库遍历」，不收敛覆盖面。

默认扫描范围 = 本次 `git diff --name-only` 改动集 + 本索引「影响面」标注的直接依赖文件；**全库扫描不是每轮动作**，在下列 5 类触发时各执行一次：

| 触发 | 做什么 | 落点 |
|---|---|---|
| 提交前 | 一次全量校验（编码、编号、禁用词、`git diff --cached --check`） | `ops/数据变更记录.md §五` 回执 |
| `CR-` 收尾 / 增删文件 / 改 `ops/commits.tsv` | 定位受影响文件并回填 | `ops/质疑与修订登记.md §4` |
| 计数、指针、编号出现不一致信号 | 全库定位漂移源 | 开 `CR-` 或 `RQ-` |
| 季度复核 | 查本索引有没有漏组、L2 条款是否过期 | `ops/数据变更记录.md §四` |
| `UNK-` 新增 / 候选集空格 / 反例检索留白 | **面向缺口的定向扩展检索**，不是全库扫 | `appendix/覆盖面候选集.md §1/§3` |

> 怎么读：C1/C2/C3、`元规则 §6` 横扫、`§7` 季度复核仍在常驻层，不受本条约束；第 5 类触发把省下的成本转投到发现缺省上，缺口的登记与复核见 `appendix/覆盖面候选集.md`。
