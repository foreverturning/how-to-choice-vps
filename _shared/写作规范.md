# 写作规范（serverless 分册）

> 适用：`docs/00-先判定要不要后端.md`、`flows/`、`cases/`、`decisions/`、`appendix/`、`emmm/`、`plans/`、`_shared/`、`ops/`、`README.md`、`00-总纲.md`。
> 优先级：`_shared/00-元规则.md`（治理层）> 本文件 > 单篇习惯。数据层变更以 `ops/数据变更记录.md` 的 `data-version` 为准。
> **规则可改**：本规范全部条款（含本行）适用 `_shared/00-元规则.md` 的 `RQ-` 质疑与 `CR-` 修订流程，默认可质疑、可修订；每轮取证须完成该文 §5 的反封闭三检查。规则与可复核事实冲突时以事实为准，并开 `CR-` 修订规则。
> 版本：`data-version: 2026-11-12.1`（与 `_shared/价格快照-2026-11.md`、`appendix/来源清单.md` 同版）。

## 一、这份规范解决什么

本分册回答一个问题：**个人制作者做纯单机小游戏或工具类小程序，能不能不买后端、0 元上线；什么时候必须买。** 所有结论必须能被读者按官方页面自己复核，因此本规范的核心是「证据分层」与「编号隔离」，而不是文风。

本册同时回答「做不做后端、要不要买机器、要花多少钱」三问。**读者先要数字，再看机制**——因此 `flows/版本更新与热更新边界.md` 的体感章放在全文最前，唯一允许直写金额的例外见第五节。

## 二、五档证据分层（硬约束）

每个断言、每个表格单元格、每条锚点，都必须标注下列五档之一，写在「证据性质」列或紧跟断言的括注里。

| 标签 | 含义 | 允许的用法 |
|---|---|---|
| `【官网明确】` | 官方文档、定价页、公告、登记表原文 | 可给原值与原单位，必须带来源编号 |
| `【官方社区·专员】` | 平台社区中可识别为官方专员的回复 | 可引用措辞，不得升级为「官方规则」 |
| `【开发者自述】` | 置顶帖中的第三方开发者、复盘博客、开源 README | 只能作实践线索，不得写成「官方允许」 |
| `【推算】` | 由多条官方事实推出、无单条明文 | 必须紧跟「假设：…」，并带量级免责 |
| `【未查到·不确定】` | 无官方明文，或两处官方口径冲突 | 只登记 `UNK-NN`，正文不给结论数字 |

三条红线：
1. **冲突只登记不裁决**：两处官方口径并存时写「两处口径并存，见 `UNK-NN`」，**不写「以 X 为准」**，不二选一，不给单一结论数字。
2. **不把开发者自述写成官方**：「可以不配置服务器域名…审核不管后台怎么设置」是社区置顶帖中第三方开发者「微喵网络」的回复，标 `【开发者自述】` 并挂 `UNK-09`。微信侧拿不到官方专员明文说「无后端可上架」，最硬的官方证据链是备案材料清单无服务器/域名/云资源、工信部《互联网信息服务备案登记表》注明「小程序、快应用无需填写域名列表和网络接入信息」、以及审核规范 3.1.5 只管功能。
3. **不把「代备案授权书」写成「免版号」**：官方用词只有前者，无「免版号」三字；是否等于法律意义豁免无明文，挂 `UNK-02`、`UNK-10`。

## 四、表格与格式

- 主报告正文表与 `appendix/术语表.md` 全部表格 **≤6 列**；表上一句「回答什么问题」、表下一句「怎么读」。
- 以下四张为**已登记附表**，按固定表头执行，不视为正文表超限：`flows/纯单机上线全流程.md` 锚点表 7 列、`flows/版本更新与热更新边界.md` 的 `VU-` 锚点表 7 列、`appendix/来源清单.md` 来源表 8 列、该文件 UNK 表 8 列。
- 空值统一写 `—`，不写 N/A、null、暂无；区间用 `–`；千分位加逗号；区间型不做精确加总须在表下注明。
- 路径一律相对当前文件，不写绝对路径、不写 `file://`、不写裸 URL 作路径。锚点：中文原样保留、去掉小节号中的点、空格转 `-`、去掉冒号与括号；跨篇引用只引到 `##` 级小节。
- 标题层级：`#` 全文唯一，`##` 对应总纲，`###` 封顶。编号写法 `## 5.1 双视角`，中间不加标点。
- 文件编码 UTF-8 无 BOM + LF（由 `.gitattributes` 的 `*.md text eol=lf` 保证）。

## 五、术语、数字与来源

- 术语首次出现必须给一句人话解释，必要时括号补英文；完整定义只在 `appendix/术语表.md` 写一次，其余文件只引 `TERM-xxx`，**不抄定义**。
- **价格与额度数字只在 `_shared/价格快照-2026-11.md` 定义**，正文只写 `S-xxx` 编号；`appendix/术语表.md` 只写编号不抄数值。
- **唯一例外**：`flows/版本更新与热更新边界.md` §0 的体感对照表允许直写具体金额，但**每格必须同时给 `S-` 编号**，使「看见数字」与「可回查」不冲突。其余位置仍只引编号。
- **来源 URL 只在 `appendix/来源清单.md` 登记**，其余文件用 `TT-`/`WX-`/`MIIT-`/`DY-`/`HW-`/`SL-`/`PLAT-`/`GL-`/`THIRD-` 编号回指。
- 流程与步骤只在 `flows/`（本轮起 `flows/` 同时承载更新边界判定与备案链路，见第七节）；证据判定标准与案例只在 `cases/`；代价核实只在 `decisions/`；免费层取样只在 `emmm/`；分支判定只在 `plans/`。
- 19.9 是取样时点的优惠价，全文禁写「长期价」「入场费」；正确口径是「数据需要离开设备之后的最低后端价」。【约定·可质疑，见 `RQ-01` 与 `_shared/00-元规则.md` §2】本句不用于推出「某类方案不存在」；候选集是否穷举按该文 §5 的 C1 检查。
- 涉及平台的名称仅作出处，不贴购买链接，不做「谁更好」的推荐性比较。

## 六、禁用与红线

禁用词：永久、终身、绝对、100%、保证、必定、最便宜、最低价、零风险、稳赚、一劳永逸。替代表：长期免费层（条款可能调整）、从公开参数看概率较低、做好备份可把损失降到很小。引用官方原文含禁用词时须加引号并紧跟定性。

其他红线：不编造来源与 sha；不写百分比描述未公布的统计（TapTap 单机占比挂 `UNK-01`）；不把「平台代做」写成「豁免」；不把「私有协议链路不产生公网流量」写成「网关免费」；不把「免费体验版暂不支持开启按量付费」与「付费套餐异常滥用自动转付费」混为一条。

## 八、文末三件套与自查

每篇正文结尾按固定顺序写：`## 本篇交付物`、`## 配套`（无配套 Lab 时写「本篇无配套 Lab」）、`## 免责声明`（本分册只提供可复核的公开信息快照，不构成上架、合规或选型结论；冲突项只登记未裁决；价格与政策会变动，下单前以官网与合同为准）。

交稿自查七条：结论前置；价格只引编号；红线扫描（禁用词、`P-`/`D-`、旧分支名、代称是否统一）；引用可点；三件套齐全；数字一致；**反封闭三检查已做并留痕**（`_shared/00-元规则.md` §5：候选集是否列全、是否做过反例检索、约定有没有被当成事实）。复核技巧：全库搜 `【推算】`、`【未查到·不确定】`、`UNK-`，逐条确认带假设或已登记。
